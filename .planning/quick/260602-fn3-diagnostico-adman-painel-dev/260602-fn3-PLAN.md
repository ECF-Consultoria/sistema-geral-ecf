<objective>
Adicionar um bloco "Diagnóstico Adman" na página `/dev/desenvolvimento` que torna o sync Adman observável: alertas proativos gerados por heurística PHP pura (sem IA, sem chamada externa) a partir de dados que já existem no banco local.

São quatro grupos de diagnóstico:
1. Empresas (com `adman_account_id`) sem sync recente — último `AdmanSyncLog.synced_at` > 48h ou nunca.
2. Syncs com erro — `AdmanSyncLog.error_message` preenchido recentemente.
3. Fila & jobs falhos — contadores das tabelas `jobs` e `failed_jobs`.
4. Anomalias de métrica `AdmanMetric` — queda forte de revenue e TACoS fora da média da própria empresa.

Cada alerta de empresa traz severidade e uma ação sugerida (re-disparar o sync via `SyncAdmanCompanyJob`).

Purpose: Permitir ao desenvolvedor admin ver o que aconteceu com o sync Adman — quem, quando, com quais erros — e disparar manualmente um re-sync, tudo sem acesso direto ao servidor.

Output:
- Novo service `app/Services/AdmanDiagnosticoService.php`.
- `DevController::index()` passando props reais + nova ação `resyncCompany()`.
- Rota POST `dev.resync` (admin-only).
- Bloco de UI "Diagnóstico Adman" em `Desenvolvimento.jsx`.
- Build de frontend atualizado (`npm run build`).
</objective>

Criar a classe `App\Services\AdmanDiagnosticoService` com docblock de classe (pt-BR) explicando que ela gera diagnósticos proativos do sync Adman lendo APENAS o banco local — sem IA e sem chamada externa.

Definir limiares como constantes públicas documentadas em pt-BR:
- `SEM_SYNC_HORAS = 48` (sem sync recente além disto vira alerta).
- `SEM_SYNC_HORAS_ALTA = 120` (severidade alta acima disto; nunca sincronizado também é alta).
- `ERRO_RECENTE_HORAS = 48` (só considerar syncs com erro dentro desta janela).
- `REVENUE_GROWTH_QUEDA = -40.0` (queda forte de revenue: revenue_growth <= -40%).
- `REVENUE_PREV_PISO = 100.0` (piso de revenue_prev_period para evitar ruído de empresas com faturamento ínfimo).
- `TACOS_DIAS_MEDIA = 14` (janela em dias da média de TACoS por empresa).
- `TACOS_MARGEM = 1.30` (TACoS anômalo se o último valor > média da janela * 1.30).
- `TOP_N = 15` (limite de itens por lista para evitar payload gigante).

Expor UM método público `gerar(): array` com PHPDoc descrevendo o shape de retorno:
```
return [
  'sem_sync'   => array<int, item>,   // empresas com adman_account_id sem sync recente
  'erros'      => array<int, item>,   // syncs recentes com error_message
  'fila'       => ['pendentes' => int, 'falhos' => int],
  'anomalias'  => array<int, item>,   // queda de revenue / TACoS anômalo
  'total'      => int,                // soma de alertas (sem_sync + erros + anomalias + fila falhos)
];
// item = ['company_id'=>int, 'empresa'=>string, 'severidade'=>'alta'|'media'|'baixa',
//         'descricao'=>string, 'acao'=>string]
```

Implementação por grupo (consultas eficientes, sem N+1):
- **sem_sync**: para empresas `Company::whereNotNull('adman_account_id')`, obter o `MAX(synced_at)` por company em UMA query agregada sobre `admin_sync_logs` (use `AdmanSyncLog::selectRaw('company_id, MAX(synced_at) as ultimo')->groupBy('company_id')->pluck('ultimo','company_id')`). Para cada empresa: se nunca sincronizou OU `ultimo` < agora-`SEM_SYNC_HORAS`, gerar item. Severidade: 'alta' se nunca OU horas desde último >= `SEM_SYNC_HORAS_ALTA`; senão 'media'. Ação: "Re-disparar sync". Ordenar por severidade (alta primeiro) e limitar a `TOP_N`.
- **erros**: `AdmanSyncLog::whereNotNull('error_message')->where('synced_at','>=',now()->subHours(ERRO_RECENTE_HORAS))->with('company')->latest('synced_at')->limit(TOP_N)->get()`. Item: severidade 'alta', descrição curta com o início do error_message (truncar ~120 chars), ação "Re-disparar sync". Pular registros cuja company seja nula.
- **fila**: `['pendentes' => DB::table('jobs')->count(), 'falhos' => DB::table('failed_jobs')->count()]`.
- **anomalias**: pegar a métrica mais recente por empresa (com adman_account_id). Para queda de revenue, usar o accessor `revenue_growth` da `AdmanMetric` mais recente: alerta se `revenue_growth <= REVENUE_GROWTH_QUEDA` E `revenue_prev_period >= REVENUE_PREV_PISO`. Para TACoS anômalo, calcular a média de `tacos` dos últimos `TACOS_DIAS_MEDIA` dias por empresa (consulta agregada `selectRaw('company_id, AVG(tacos) as media')` filtrando `reference_date >= today-14`); marcar anomalia se o `tacos` da métrica mais recente > média * `TACOS_MARGEM` E média > 0. Severidade: 'alta' para queda de revenue, 'media' para TACoS anômalo. Descrição em pt-BR com os números (ex.: "Revenue caiu 47% vs período anterior" / "TACoS 0,38 acima da média 0,25 dos últimos 14 dias"). Ação "Re-disparar sync". Limitar a `TOP_N`.

Carregar nomes de empresa via eager loading / pluck em lote — NUNCA consultar Company dentro de loop. Comentários em pt-BR. Sem fenced code na lógica final do arquivo; o pseudocódigo acima é guia.
