# Quick Task 260610-f69 — Dashboard Admin: filtros + widget carteira (SUMMARY)

## Resumo

Fix consolidado de 4 bugs no Dashboard Admin (`/dashboard` quando role=admin) que
afetavam tanto os filtros do topo quanto o widget "Carteira Portfólio por
Profissional". Causa-raiz comum: o código lia `users.role` (legacy: admin/
consultor/mentor) como fonte da verdade pra decidir quem é Analista vs
Estrategista, mas a taxonomia atual vive em `user_setores.cargo_id` →
`cargos.slug` (setor Performance). Vários estrategistas têm `role=consultor`
no banco e caíam no select errado / em branch errado do widget.

Commit único: `2d29c6d` em pt-BR.

## Bugs corrigidos

### Bug 1 — Filtro "Analistas" misturava Estrategistas

**Antes** (`Admin.jsx:144`):
```jsx
const consultores = (users || []).filter(u => u.role === 'consultor');
```

Como Nathalia, Rubens, Débora e Douglas têm `users.role='consultor'` mesmo sendo
Estrategistas, apareciam no select de Analistas.

**Depois:** o select agora consome a prop `analistas` derivada via cargo no
pivot (`user_setores.cargo_id` → `cargos.slug='analista'` no setor Performance).

### Bug 2 — Filtro "Estrategistas" só mostrava Luiz Henrique

**Antes** (`Admin.jsx:145`):
```jsx
const mentores = (users || []).filter(u => u.role === 'mentor');
```

Só Luiz tem `role=mentor`. Os outros 4 estrategistas (Nathalia, Rubens, Débora,
Douglas) ficavam fora.

**Depois:** select consome `estrategistas` derivada via
`cargos.slug='estrategista'` no pivot.

### Bug 3 — Sem cross-filter

Antes os dois selects eram totalmente independentes. Selecionar Stefani não
restringia estrategistas aos que trabalham com ela.

**Depois:** nova prop `combinacoes` (lista de pares analista_id/estrategista_id
que dividem ao menos uma empresa em `company_users`). O frontend filtra
dinamicamente:

```jsx
const analistasFiltrados = filters.estrategista_id
    ? analistas.filter(a => combinacoes.some(c =>
        String(c.analista_id) === String(a.id) &&
        String(c.estrategista_id) === String(filters.estrategista_id)
      ))
    : analistas;
// e simétrico para estrategistasFiltrados
```

### Bug 4 — Widget "Carteira Portfólio por Profissional" incompleto + TACOS zerado

Três problemas combinados:

1. `$users->map(...)` iterava sobre a lista legacy filtrada por `role` — não
   listava estrategistas reais que têm `role=consultor` no banco.
2. Branch interno usava `$u->isMentor()` (só Luiz cai como mentor); demais
   estrategistas iam no else e procuravam em `$c->consultor` em vez de
   `$c->estrategista` → carteira vazia.
3. `avg('tacos')` calculava média dos `tacos` diários da carteira. Empresas sem
   ads ativo têm `tacos=0` em todos os dias e diluíam o avg → ficava ~0%.
4. `$companies` era a lista FILTRADA do topo → quando user filtra por uma
   empresa, carteira dos outros sumia.

**Depois:**

```php
$todosProfissionais = $analistas->map(fn($u) => ['user' => $u, 'tipo' => 'analista'])
    ->concat($estrategistas->map(fn($u) => ['user' => $u, 'tipo' => 'estrategista']));

$userPortfolios = $todosProfissionais->map(function ($item) use ($since) {
    $u    = $item['user'];
    $tipo = $item['tipo'];
    $companyIds = ($tipo === 'estrategista')
        ? $u->estrategistaCompanies()->where('active', true)->pluck('companies.id')
        : $u->consultorCompanies()->where('active', true)->pluck('companies.id');
    if ($companyIds->isEmpty()) return null;

    $uMetrics = AdmanMetric::whereIn('company_id', $companyIds)
        ->where('reference_date', '>=', $since->toDateString())->get();

    $totalRevenue  = (float) $uMetrics->sum('revenue');
    $totalAdSpend  = (float) $uMetrics->sum('ad_spend');
    $tacosCarteira = $totalRevenue > 0
        ? round(($totalAdSpend / $totalRevenue) * 100, 2)
        : null;
    // ...
});
```

Resultados:
- Widget é uma VISÃO COMPLETA da equipe (independente de filtros do topo)
- TACOS = `SUM(ad_spend) / SUM(revenue) * 100`, null sem revenue
- Cada item inclui `tipo` (analista/estrategista) para o label correto no card

### Decisão técnica — `whereExists` em vez de `whereHas` aninhado

A opção alternativa `whereHas('setores', fn... whereHas('cargos', fn => slug=X))`
**não funcionaria** porque matchearia "user em setor cujo CARGOS table contém
slug=X" — mas Setor Performance tem AMBOS os cargos (analista e estrategista),
então retornaria todo mundo do Performance nos dois lados.

A regra correta é filtrar pelo `cargo_id` GUARDADO no pivot `user_setores` para
este user específico. O `whereExists` faz exatamente isso ao juntar pivot +
cargos diretamente.

Schema confirmado:
- `user_setores`: id, user_id, setor_id, **cargo_id** (nullable, FK cargos),
  is_principal, assigned_at
- `cargos`: id, setor_id, nome, **slug**, meta_publicacoes, ordem, active
