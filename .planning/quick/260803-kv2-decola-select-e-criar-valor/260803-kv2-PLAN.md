# Painel Polos — Decola como select + fix do "Criar novo valor"

## Contexto

Dois pedidos numa tacada só, ambos em `/mlb/polos-painel` (lente **Produtos & Publicação** e
lente **Geral**):

1. **Decola deixa de ser booleano.** Hoje a coluna é um `EditToggle` Sim/Não sobre a coluna
   `mlb_implementacoes.decola` (tipo `boolean`). Precisa virar um select como os demais, com
   as opções **Sim**, **Não** e **Mensagem Enviada**, e aceitar o "＋ Criar novo valor…".

2. **Bug: "＋ Criar novo valor…" não salva.** Ao criar um valor pelo `window.prompt`, nada
   acontece — o valor não persiste nem aparece na lista.

## Diagnóstico do bug (causa-raiz)

`EditSelect` (`resources/js/Pages/Polos/Painel.jsx:415-423`) chama `onSave(e, campo, novo)`
com o valor digitado. O `salvarCampo` faz `router.patch(mlb.implementacao.bloco.<bloco>)`.

Os endpoints de bloco validam os campos do onboarding com `Rule::in(...)` contra o catálogo
fixo do model:

| Campo | Validação hoje | Arquivo |
|---|---|---|
| `acesso_colaborador` | `Rule::in(ONB_ACESSO_COLABORADOR_OPCOES)` | `MlbImplementacaoController.php:727` |
| `planilha_produtos` / `listagem` / `publicacao` | `Rule::in(...)` | `:758-760` |
| `me1` / `integradora` / `places` / `erp` | `Rule::in(...)` | `:791-794` |
| `polo` / `fase` | `Rule::in(...)` | `:682-683` |

Valor fora do catálogo → **422**. O Inertia não recarrega, nenhum erro aparece na grade →
exatamente o sintoma relatado ("não salva, não aparece o que criei").

Note que `status_entrada`, `chance_entrada` e `reuniao_onboarding` **já** eram texto livre
(comentário no código: *"texto livre (aceita 'criar novo valor')"*) — e esses funcionam. Ou
seja: o desenho pretendido é texto livre; faltou aplicar aos demais.

O front já está pronto para isso: `valoresPresentes` (`Painel.jsx:597-601`) recolhe os valores
presentes nos dados e mescla no catálogo do select — o valor criado reaparece para todas as
linhas após o reload.

## Decisões

- **`decola` migra de `boolean` para `string(60)`.** Não dá para representar 3+ valores num
  booleano. Migration converte o histórico: `1 → 'Sim'`, `0 → 'Não'`, `null → null`.
- **`fase` continua fechada** (`Rule::in`) e **perde** o "＋ Criar novo valor…". A fase alimenta
  `MlbEmpresa::FASE_PARA_PROJETO`, que decide se a empresa é do projeto POLOS — uma fase
  inventada faria a empresa sumir do painel silenciosamente. `polo` passa a aceitar valor novo
  (região nova é evento de negócio real).
- **Limite de tamanho** em vez de enum: `max:150` (mesmo padrão já usado em `status_entrada`).
  O catálogo do model continua sendo a fonte das opções *sugeridas*.

## Tarefas

1. **Migration** — `decola` boolean → string(60), convertendo dados existentes.
2. **Model** `MlbImplementacao` — remover cast `boolean`; adicionar `ONB_DECOLA_OPCOES`.
3. **`MlbImplementacaoController`** — `decola` como string; trocar os `Rule::in` dos campos
   criáveis por texto livre; expor `ONB_DECOLA_OPCOES` no payload da ficha.
4. **`PolosController`** — `decola` deixa de ser `(bool)` no payload e sai do `$BOOL` do
   `painelBulk`; expor `opcoes.decola`.
5. **`SyncPolosPlanilha`** — `Decola` sai de `BOOL_IMPL` e vira coluna de texto normalizada.
6. **`Painel.jsx`** — `EditToggle` → `EditSelect` na coluna Decola; `decola` entra em
   `CAMPOS_CRIAVEIS`; edição em massa vira select; `fase` sem opção de criar; cor de
   "Mensagem Enviada" (âmbar = em progresso).
7. **`OnboardingFicha.jsx`** — modal Produtos: `ToggleSimNao` → `Select`; badge do resumo.
8. **Testes** — atualizar `Phase33OnboardingFichaTest` (decola string) e cobrir o valor
   customizado (o bug do item 2).
9. `npm run build` + deploy.
