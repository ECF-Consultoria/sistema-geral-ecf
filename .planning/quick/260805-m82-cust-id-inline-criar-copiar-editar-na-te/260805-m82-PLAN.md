# Quick 260805-m82 — Cust ID inline no Onboarding (/mlb/implementacao)

## Objetivo

Replicar na listagem de `/mlb/implementacao` o mesmo esquema de Cust ID que já existe no
Painel Polos: **copiar** (chip clicável), **criar** (botão `＋ cust_id` quando a empresa
não tem) e **editar** (lápis que reabre o input já preenchido). Hoje a tela de Onboarding
não mostra o cust_id — pra cadastrar/corrigir é preciso ir até `Mlb/Empresas.jsx`.

Referência da UX: `resources/js/Pages/Polos/Painel.jsx` (`CustIdChip` + `CustIdCell`,
DEPLOYADO em 260731 / `d88cabc4`).

## Contexto técnico

- `/mlb/implementacao` lista `MlbImplementacao` com `empresa` (`MlbEmpresa`) eager-loaded;
  `MlbImplementacaoController@index` monta o array por empresa e **não** envia `cust_id`.
- `cust_id` é coluna simples e fillable em `MlbEmpresa`.
- Endpoint de escrita já existe e é dedicado (não zera outros campos):
  `PATCH mlb.empresas.cust-id` → `MlbController@updateCustIdEmpresa`.
- **Divergência de gate:** o endpoint exige `mlb.empresas`; o Onboarding abre para
  `mlb.implementacao` / cargos de publicação também. Sem ajuste, parte do público da tela
  veria o botão e tomaria 403 ao salvar.

  unificou Onboarding + Painel Polos).
- `Painel.jsx` passa a importar do módulo; comportamento inalterado.
- **verify:** `npm run build` compila; nenhuma outra referência a `CustIdChip` órfã.
- **done:** Painel Polos continua com chip/＋/lápis idênticos.

### T2 — Backend expõe `cust_id` e libera a escrita para o público do Onboarding
**Arquivos:** `app/Http/Controllers/MlbImplementacaoController.php`,
`app/Http/Controllers/MlbController.php`

- `index()`: incluir `'cust_id' => $e->cust_id` no array mapeado por empresa.
