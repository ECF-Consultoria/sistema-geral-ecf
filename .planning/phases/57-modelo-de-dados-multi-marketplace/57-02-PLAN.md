# Wave 2 — Smoke tests dos 3 consumidores críticos

## Objective

Validar via smoke tests que os 3 consumidores mais críticos de `companies.marketplace` (Dashboard, Sugadores, /performance) continuam funcionando após:
1. Introdução da tabela pivot `company_marketplaces`
2. Uso dos accessors novos que leem da pivot

Testes DELIBERADAMENTE minimalistas: verificar que rotas retornam 200 e não 500. Não validar valores específicos (isso é UAT em prod). O objetivo é pegar regressões grosseiras (SQL error, undefined method, null pointer) causadas pelo modelo novo.

Também rodar backfill local (se MariaDB voltou) OU documentar bloqueio pra Wave 3 deployar direto em prod.

```php
<?php

namespace Tests\Feature\Phase57;

use App\Models\Company;
use App\Models\CompanyMarketplace;
use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class SugadoresSmokeTest extends TestCase
{
    use RefreshDatabase;

    /** @test */
    public function listagem_sugadores_carrega_com_pivot(): void
    {
        $admin = User::factory()->create(['role' => 'admin']);
        $company = Company::factory()->create([
            'marketplace' => 'meli',
            'adman_account_id' => 'ADM_S1',
        ]);
        CompanyMarketplace::factory()->create([
            'company_id' => $company->id,
            'marketplace' => 'meli',
            'adman_id' => 'ADM_S1',
            'is_primary' => true,
        ]);

        $response = $this->actingAs($admin)->get('/sugadores');

        $response->assertStatus(200);
    }

    /** @test */
    public function drilldown_sugadores_por_empresa_carrega(): void
    {
        $admin = User::factory()->create(['role' => 'admin']);
        $company = Company::factory()->create([
            'marketplace' => 'meli',
            'adman_account_id' => 'ADM_S2',
        ]);
        CompanyMarketplace::factory()->create([
            'company_id' => $company->id,
            'marketplace' => 'meli',
            'adman_id' => 'ADM_S2',
            'is_primary' => true,
        ]);

        $response = $this->actingAs($admin)->get("/sugadores/empresa/{$company->id}");

        // 200 se empresa tem sugadores; 404 é aceitavel se rota exige ter sugadores
        // O smoke aqui é: NAO 500 (erro de accessor/query)
        $this->assertContains($response->status(), [200, 404], "Rota não deve retornar 5xx");
    }
}
```

**Nota:** o drilldown pode retornar 404 se a rota exige `Company` com pelo menos 1 sugador. Isso é OK — o objetivo é garantir que NÃO retorna 500 (SQL error/undefined method).
