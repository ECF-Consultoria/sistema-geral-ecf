<objective>
Fechar o loop de UX da degradação graciosa (SC2/SC3) na tela `Performance/Index.jsx`,
consumindo o payload do Plan 106-02 (`aquecendo: bool` + linhas `calculando: true`).

Comportamento:
1. Ler a prop nova `aquecendo` (default false) e a flag `calculando` de cada linha.
2. Nas linhas `calculando`, renderizar estado "calculando…" (sem número/badge de faixa)
   em vez de nota — reaproveitando o mesmo bloco de transparência que a tela já usa
   para `sem_carteira`/`score_status` (RankingConsultoria).
3. Enquanto `aquecendo === true`, poll parcial via
   `router.reload({ only: ['ranking','aquecendo'], preserveScroll: true, preserveState: true })`
   a cada ~6s — reusando EXATAMENTE o padrão do Modo TV (~linha 1685). Parar quando
   `aquecendo` virar false OU ao atingir o teto (~20 tentativas ≈ 2min), exibindo aí
   "Demorando mais que o esperado" com opção de recarregar manual.
4. Modo "Em curso" (aquecendo=false) segue idêntico — sem poll, sem "calculando…".

Purpose: transformar o pior caso (timeout → tela branca) em uma espera visível e
autorresolvente. É a metade cliente do SC2.
Output: `Index.jsx` atualizado + `npm run build` + checkpoint visual (a tela muda).

**FRONTEIRA:** só `Performance/Index.jsx`. NÃO tocar backend. O ramo Polos
(`isPolos`/`PolosDashboard`) fica intocado — a degradação é só do ranking de consultoria.
</objective>
