`RefreshDatabase` — é análise estática do texto das duas migrations, não roda banco.

Um helper privado carrega o conteúdo de cada migration **com os comentários removidos** —
primeiro tirando blocos `/* … */` (modificador `s`) e depois linhas `//` (modificador `m`).
⚠️ Este passo é obrigatório e não é detalhe: as duas migrations desta fase **contêm a palavra
`enum` e as palavras `1830`/`1059` dentro de comentários explicativos**. Sem remover os
comentários, a guarda acusaria a si mesma e o teste seria inútil (auto-invalidante).

Um provider/array com os dois caminhos de migration; cada teste itera sobre os dois arquivos e
usa mensagem de asserção que cite o arquivo e a armadilha.

Testes:

1. `nenhuma_migration_da_fase_usa_coluna_de_tipo_restrito` — o código sem comentários não
   contém `->enum(`. Mensagem citando a D-04 e o CHECK enforçado no SQLite.
2. `toda_fk_null_on_delete_tem_coluna_nullable` — para cada ocorrência de `nullOnDelete` no
   código sem comentários, extrair o nome da coluna do `foreign('X'` (ou `foreignId('X'`)
   correspondente e afirmar que o mesmo arquivo declara essa coluna com `->nullable()`.
   Mensagem citando o erro **1830** e o fato de o SQLite não pegar.
3. `nenhum_indice_ou_chave_e_anonimo` — toda chamada `->unique(`, `->index(` e `->foreign(`
   no código sem comentários tem um segundo argumento que é uma string entre aspas (o nome
   explícito). Mensagem citando o erro **1059** e a consequência silenciosa (tabela criada
   sem o índice, migration `Pending`).
4. `todo_nome_de_indice_cabe_em_64_caracteres` — extrair todos os nomes explícitos capturados
   no teste anterior e afirmar `strlen() <= 64` para cada um, com margem confortável
   reportada na mensagem (nome + comprimento).
5. `nenhuma_migration_da_fase_cria_coluna_de_prazo` — o código sem comentários não contém
   `expira_em` nem `deadline`. É a guarda executável da **D-03** (prazo é a Fase 127); sem
   ela, uma sessão futura pode "ajudar" adicionando a coluna fora de fase.
6. `as_duas_migrations_da_fase_existem` — afirmar que os dois caminhos existem em disco, para
   o teste falhar de forma legível se alguém renomear o arquivo.
