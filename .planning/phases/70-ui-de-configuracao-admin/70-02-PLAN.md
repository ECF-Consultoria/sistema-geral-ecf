<objective>
Entregar o **backend CRUD de perguntas de templates NPS** — 4 endpoints REST nested sob `/nps/configuracao/templates/{template}/perguntas/…` com regras de negócio críticas: (a) tipo='escala' auto-cria 5 options; (b) tipo é imutável após criação; (c) reorder via SWAP transacional idêntico ao pattern Phase 33; (d) scoped route model binding para 404 quando pergunta não pertence ao template. Cobre 100% dos REQs NPS-C-02 (adicionar/editar/reordenar/excluir perguntas) e NPS-C-04 (dimensão + obrigatoriedade).

Purpose: Perguntas são o coração do template — sem CRUD dinâmico, o admin fica preso ao seed "NPS Padrão" da Phase 68. O auto-generate de 5 options em tipo=escala é o "açúcar sintático" travado no research §5 — evita cliques manuais para o caso 90% dos casos de uso (perguntas de escala 1-5).

<action>
Criar `app/Http/Controllers/NpsTemplateQuestionController.php` no namespace `App\Http\Controllers`.

Método `store(StoreNpsTemplateQuestionRequest $request, NpsTemplate $template)`:

Fluxo transacional em `DB::transaction(function () use ($request, $template) { ... })`:

1. `$data = $request->validated();`
2. `$data['template_id'] = $template->id;`
3. `$data['ordem'] = ($template->questions()->max('ordem') ?? 0) + 1;` — última posição
4. `$data['obrigatoria'] = $data['obrigatoria'] ?? true;` — default true
5. `$question = NpsTemplateQuestion::create($data);`
6. **Se `$question->tipo === NpsTemplateQuestion::TIPO_ESCALA`:** loop `for ($i = 1; $i <= 5; $i++)` criando 5 options com `NpsTemplateOption::create(['question_id' => $question->id, 'label' => (string)$i, 'peso' => $i, 'ordem' => $i])`
7. Fora da transaction: `return back()->with('success', 'Pergunta criada.')` — Inertia flash

**Motivo do DB::transaction:** se a criação da pergunta commitar mas o loop de options falhar (ex: constraint violada), ficaríamos com uma pergunta escala sem opções — quebra o invariante "escala tem exatamente 5 opções".

Type-hint EXATO: `store(StoreNpsTemplateQuestionRequest $request, NpsTemplate $template)`.
</action>

Em `routes/web.php`, dentro do MESMO grupo `Route::middleware(['auth','role:admin'])` das rotas do Plan 70-01, adicionar as 4 rotas nested — logo depois das rotas de templates (Plan 70-01):

```php
// ─── Phase 70 Plan 02 — CRUD perguntas dos templates ────────────────
Route::post  ('/nps/configuracao/templates/{template}/perguntas',
    [NpsTemplateQuestionController::class, 'store'])
    ->name('nps.configuracao.templates.perguntas.store');

Route::put   ('/nps/configuracao/templates/{template}/perguntas/{pergunta}',
    [NpsTemplateQuestionController::class, 'update'])
    ->scopeBindings()
    ->name('nps.configuracao.templates.perguntas.update');

Route::delete('/nps/configuracao/templates/{template}/perguntas/{pergunta}',
    [NpsTemplateQuestionController::class, 'destroy'])
    ->scopeBindings()
    ->name('nps.configuracao.templates.perguntas.destroy');

Route::post  ('/nps/configuracao/templates/{template}/perguntas/{pergunta}/mover',
    [NpsTemplateQuestionController::class, 'mover'])
    ->scopeBindings()
    ->name('nps.configuracao.templates.perguntas.mover');
```

O `->scopeBindings()` faz o Laravel automaticamente escopar `{pergunta}` ao `{template}` via convenção `Model::where('template_id', $template->id)` — sem isso, `NpsTemplateQuestion::find(X)` acharia qualquer pergunta e o guard interno seria a única defesa. **Com `scopeBindings()`, o Laravel devolve 404 direto se a pergunta não pertence ao template — segurança em profundidade.**

Adicionar `use App\Http\Controllers\NpsTemplateQuestionController;` no topo.

**Reference (padrão do model binding scoped Laravel 12):** o nome do parâmetro `{pergunta}` bate com o segundo argumento do método (`NpsTemplateQuestion $pergunta`). O `scopeBindings()` implicit resolve via `where('template_id', $template->id)`.
</action>
