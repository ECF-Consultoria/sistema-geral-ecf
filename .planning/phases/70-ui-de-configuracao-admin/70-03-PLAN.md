Este plan libera a customização completa que a UI do Plan 70-05 vai consumir.

<research_reference>
Research §5 (v15-nps-templates-schema.md):
- Peso 1..5 hardcoded como limite — admin ajusta labels/pesos livremente respeitando 1..5
- UI bloqueia peso > 5 até nova REQ

Research §1 (v15-nps-templates-schema.md):
- `option_peso_snapshot` é congelado no submit → mudanças futuras no peso não afetam histórico
- `NpsScoreCalculator::compute()` faz `AVG(option_peso_snapshot)` — precisa de pelo menos 1 answer com peso para retornar float; sem answers retorna null (semântico "sem dado")

**Consequência do guard:** se uma pergunta ficar sem opções, cliente não consegue responder → survey trava. Portanto: (a) pergunta tipo=escala nunca deve ficar com < 1 opção; (b) pergunta tipo=opcoes com 0 opções é estado inválido no form público (UI Phase 71 vai renderizar aviso). Aqui protegemos o caso escala; opcoes fica sob responsabilidade do admin (pattern "warn but allow").
</research_reference>

Adicionar 3 métodos no `NpsTemplateOptionController`:

**`update(UpdateNpsTemplateOptionRequest $request, NpsTemplate $template, NpsTemplateQuestion $pergunta, NpsTemplateOption $opcao)`:**
- Guard duplo: `abort_if($pergunta->template_id !== $template->id, 404); abort_if($opcao->question_id !== $pergunta->id, 404);`
- `$opcao->update($request->validated());`
- `return back()->with('success', 'Opção atualizada.');`

**`destroy(NpsTemplate $template, NpsTemplateQuestion $pergunta, NpsTemplateOption $opcao)`:**
- Guard duplo idêntico
- **Guard invariante:** se `$pergunta->tipo === NpsTemplateQuestion::TIPO_ESCALA && $pergunta->options()->count() <= 1` → `abort(422, 'Uma pergunta de escala precisa ter ao menos 1 opção.');`
- `$opcao->delete();`
- `return back()->with('success', 'Opção removida.');`

**`mover(Request $request, NpsTemplate $template, NpsTemplateQuestion $pergunta, NpsTemplateOption $opcao)`:**
- Guard duplo idêntico
- Valida direcao: `$direcao = $request->validate(['direcao' => 'required|in:up,down'])['direcao'];`
- Encontra vizinha SCOPED por `question_id`:
  - `up`: `NpsTemplateOption::where('question_id', $pergunta->id)->where('ordem', '<', $opcao->ordem)->orderByDesc('ordem')->orderByDesc('id')->first();`
  - `down`: análogo invertido
- No-op se `!$vizinha`
- SWAP em `DB::transaction(function () use ($opcao, $vizinha) { $tmp = $opcao->ordem; $opcao->update(['ordem' => $vizinha->ordem]); $vizinha->update(['ordem' => $tmp]); });`
- `return back();`
</action>
