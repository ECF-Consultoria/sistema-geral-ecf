instância + flag `wasRecentlyCreated`. Se `false` → 2º request com mesmo event_id →
NÃO despacha Job, retorna 200 idempotente. Race condition resolvida pelo UNIQUE
constraint do MySQL/SQLite (Laravel pega exceção e retorna o registro existente).

## Riscos residuais (documentados — não bloqueiam o plan)

**R-01: Race condition no firstOrCreate — 2 requests simultâneos com mesmo event_id**
- Mitigação: UNIQUE constraint do DB resolve. Laravel captura `QueryException` (duplicate key) e retorna o registro existente. Comportamento idempotente garantido. Testar com test específico (mesmo event_id 2× em sequência → 1 dispatch só).

**R-02: ECF Drive pode mandar payload com BOM ou whitespace diferente**
- Mitigação: `$request->getContent()` retorna raw body byte-by-byte. HMAC calculado em cima do raw — mesmo bytes que o parceiro usou. CONTEXT pitfall 1.

**R-03: `processed_at` pode ficar NULL eternamente se Job crashar antes de marcar processed**
- Mitigação: hook `failed()` do Job atualiza para `status='failed'` + `error_message`. Queue worker do Laravel chama `failed()` após esgotar `tries`.

**R-04: Cache::forget de chave que não existe é no-op silencioso — NÃO falha**
- Mitigação: comportamento esperado. Logamos no canal ecf-webhooks pra auditoria.

**R-05: `Notification::send` falha (DB down) → Job marca como failed**
- Mitigação: Job tem `tries=3` default. Retry pega DB de volta na maioria dos casos. Hook `failed()` registra `error_message`.

**R-06: Worker não está rodando em prod no momento do recebimento**
- Mitigação: Phase 18.5 já configurou supervisor `ecf-worker:*`. Confirmado em prod (memory `project_legacy_columns_rename` menciona deploy validado). Webhook gravado em `webhook_deliveries` + Job persiste em `jobs` table — worker pega quando subir.

**R-07: ECF Drive retenta o mesmo event_id 5× (2,4,8,16,32 min)**
- Mitigação: idempotência via UNIQUE+firstOrCreate cobre. 5 tentativas = 5 INSERTs falhando + 5 responses 200 sem dispatch extra. Comportamento idempotente comprovado.

**R-08: Lista hardcoded de chaves de cache vai ficar desatualizada conforme novas chaves surgem**
- Mitigação: aceitar. Cache em chave desatualizada expira em 1h naturalmente. Pior caso: 1h de dados stale após etl.completed em chaves não listadas. Documentar em comentário do Job onde adicionar chaves novas. Phase futura: tags Redis quando promover store.

**R-09: Smoke W3 falha se IP do servidor admin for blocado pelo painel ECF Drive**
- Mitigação: CONTEXT pitfall 7 menciona — sem IP allowlist documentado. Se falhar, usuário aciona suporte parceiro. Não bloqueia plano.

**R-10: Em Windows DEV (xampp local) o canal `ecf-webhooks` pode ter problema de path (storage/logs)**
- Mitigação: `storage_path('logs/ecf-webhooks.log')` é cross-platform no Laravel. Sem hardcode de `/`.
