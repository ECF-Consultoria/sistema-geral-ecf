<objective>

Regra dedup:
- Se `status='completed' AND completed_at IS NOT NULL`: survey CONTA pra dedup
- Caso contrário: survey NÃO conta (pending / expired ainda podem ser regeradas)

MySQL/MariaDB:
```sql
ALTER TABLE nps_surveys ADD COLUMN dedup_key VARCHAR(64)
  GENERATED ALWAYS AS (
    CASE WHEN status = 'completed' AND completed_at IS NOT NULL
         THEN CONCAT(company_id, '|', DATE_FORMAT(month_reference, '%Y-%m'), '|', template_id)
    END
  ) VIRTUAL;
ALTER TABLE nps_surveys ADD UNIQUE INDEX nps_surveys_dedup_uniq (dedup_key);
```

SQLite 3.31+:
```sql
CREATE UNIQUE INDEX nps_surveys_dedup_uniq
  ON nps_surveys(company_id, month_reference, template_id)
  WHERE status = 'completed' AND completed_at IS NOT NULL;
```

    **Docblock pt-BR** (topo do arquivo):
    - Referência: Phase 68 Plan 04, REQ NPS-A-01
    - Motivação: bloqueio DB-level de dedup mensal — segundo NPS pra mesma `(company_id, month_reference, template_id)` completo trava com `QueryException 23000`. Phase 69 vai capturar essa exception no `NpsController` e mostrar tela "Já respondida no mês" (research §2 + NPS-B-03)
    - Split por driver: MySQL/MariaDB usa virtual generated column + unique index; SQLite usa partial unique index nativo (3.31+)
    - Idempotência: guard antes de qualquer statement por driver

    **`up()`:**

    ```php
    public function up(): void
    {
        $driver = DB::connection()->getDriverName();

        if ($driver === 'sqlite') {
            // Idempotência: checar se índice já existe via sqlite_master
            $existe = DB::selectOne("SELECT name FROM sqlite_master WHERE type='index' AND name='nps_surveys_dedup_uniq'");
            if ($existe) {
                Log::info('[Phase 68 Plan 04] Índice nps_surveys_dedup_uniq já existe (SQLite) — skip');
                return;
            }

            // Partial unique index nativo (SQLite 3.31+)
            DB::statement("CREATE UNIQUE INDEX nps_surveys_dedup_uniq
                ON nps_surveys(company_id, month_reference, template_id)
                WHERE status = 'completed' AND completed_at IS NOT NULL");
            return;
        }

        // MySQL / MariaDB path
        if (Schema::hasColumn('nps_surveys', 'dedup_key')) {
            Log::info('[Phase 68 Plan 04] Coluna dedup_key já existe (MySQL/MariaDB) — skip');
            return;
        }

        // Virtual generated column — NULL quando survey não conta pra dedup
        DB::statement("ALTER TABLE nps_surveys ADD COLUMN dedup_key VARCHAR(64)
            GENERATED ALWAYS AS (
              CASE WHEN status = 'completed' AND completed_at IS NOT NULL
                   THEN CONCAT(company_id, '|', DATE_FORMAT(month_reference, '%Y-%m'), '|', template_id)
              END
            ) VIRTUAL");

        DB::statement("ALTER TABLE nps_surveys ADD UNIQUE INDEX nps_surveys_dedup_uniq (dedup_key)");
    }
    ```

    **`down()`:**

    ```php
    public function down(): void
    {
        $driver = DB::connection()->getDriverName();

        if ($driver === 'sqlite') {
            DB::statement("DROP INDEX IF EXISTS nps_surveys_dedup_uniq");
            return;
        }

        // MySQL/MariaDB — drop unique primeiro, depois a coluna
        if (Schema::hasColumn('nps_surveys', 'dedup_key')) {
            DB::statement("ALTER TABLE nps_surveys DROP INDEX nps_surveys_dedup_uniq");
            DB::statement("ALTER TABLE nps_surveys DROP COLUMN dedup_key");
        }
    }
    ```

    **Imports obrigatórios:**

    **Comentários pt-BR obrigatórios:**
    - Explicar por que virtual column em vez de `Schema::table(...)->virtualAs(...)` (research §2: Laravel emite sintaxe incompatível com SQLite in-memory nesse caso)
    - Explicar por que `DATE_FORMAT(month_reference, '%Y-%m')` (garantir formato consistente independente de storage type — MySQL guarda date como YYYY-MM-DD)
    - Explicar que NULL não colide com NULL em unique (comportamento nativo dos 2 bancos — surveys pending não conflitam)
    - Explicar que o guard `QueryException 23000` no controller entra na Phase 69 (NPS-B-03)

    **IMPORTANTE:** o `down()` no path SQLite depende de o partial index existir. Se a coluna `dedup_key` NÃO foi criada no SQLite (correto — SQLite usa partial index sem coluna), o `down()` só dropa o índice.

    **Ordem de migration timestamp:** `2026_07_07_100005` roda APÓS `100004` (seed retro-associação). Isso é crítico: se essa migration rodasse ANTES do seed, retro-associação daria conflito em surveys legadas duplicadas (improvável mas defensivo). Ordem timestamp preserva.
