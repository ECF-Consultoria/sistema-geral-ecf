  <name>Task 1: Skip de serviço isento dentro do ContratoClicksignService</name>
  <files>app/Services/Clicksign/ContratoClicksignService.php</files>
  <action>
`iniciarParaEmpresa()` itera **todos** os `ContratoServico` ativos da empresa (linha 86). Uma
empresa que tem `Gestão` + `Polos` geraria hoje um `ContratoAssinatura` para Polos também —
violação direta do SC0. A isenção precisa existir aqui, e não só no orquestrador, porque a
Fase 131 vai expor um botão que chama este método direto.

Dentro do `foreach` de `$contratosServico`, **antes** do guard `emAndamentoDoServico`,
acrescentar:
- se `optional($contratoServico->servico)?->exigeContrato() === false` →
  `$pulados[] = ['servico_id' => $contratoServico->servico_id, 'motivo' => 'servico_isento'];`
  e `continue;`

Regras:
- Reusar a chave `pulados` que já existe no contrato de retorno — **não** criar chave nova, para
  não quebrar quem já lê o retorno (Fase 127).
- O motivo é `'servico_isento'`, distinto de `'ja_em_andamento'`.
- Se `$contratoServico->servico` for `null` (dado órfão), tratar como **exigindo** contrato
  (não pular) — o default seguro do plano 01 vale aqui também; nunca isentar por ausência de dado.
- Comentário pt-BR citando D-03/SC0 e o motivo de a checagem morar aqui **além** do orquestrador
  (Fase 131 chama este método direto).
- **Não** mexer em mais nada deste método: as etapas 1, 1b e o resto do laço ficam intactos.
  </action>

  <name>Task 2: GatilhoContratoAdministrativoService — o orquestrador único</name>
  <files>app/Services/Contratos/GatilhoContratoAdministrativoService.php</files>
  <action>
Criar `app/Services/Contratos/GatilhoContratoAdministrativoService.php`, namespace
`App\Services\Contratos`, com construtor por promoção:
`__construct(private PendenciasComerciaisService $pendencias, private ContratoClicksignService $clicksign)`.

Métodos públicos:

**`public function avaliar(Company $company): array`** — decide, **sem nenhum efeito colateral**
(não cria nada, não despacha job). Sequência exata, que É a D-02:
1. **Isenção (D-03/SC0).** Carregar os `ContratoServico` ativos da empresa com `servico`. Se
   NENHUM deles tem `servico->exigeContrato() === true` → retornar
   `['status' => 'isento', 'pendencias' => [], 'motivo' => 'nenhum servico exige contrato']`.
   Empresa 100% Polos morre aqui: não é avaliada, não é pendente, não aparece em lugar nenhum.
2. **Reentrância.** Se `ContratoAssinatura::emAndamentoDaEmpresa($company->id)` → retornar
   `['status' => 'ja_em_andamento', 'pendencias' => []]`. Esta checagem vem ANTES dos portões
   de propósito (D-04: "o ideal é nem chegar lá" — não confiar só na trava do banco).
3. **1º portão (D-02).** `$slugs = $this->pendencias->calcularUniversais($company)`. Se != [] →
   retornar `['status' => 'aguardando_comercial', 'pendencias' => $slugs]`.
4. Retornar `['status' => 'elegivel', 'pendencias' => []]`.

**`public function aguardandoComercial(Company $company): bool`** — `avaliar()['status'] === 'aguardando_comercial'`.
Docblock pt-BR registrando a decisão de discricionariedade: o estado `aguardando_comercial`
do Success Criteria 3 é **derivado, não persistido** — a "marca" é a combinação de serviço que
exige contrato + pendência aberta + ausência de `ContratoAssinatura`. Nada é gravado em
`companies.status`, que já tem semântica própria em uso (`pendente`/`ativo`) e colidiria.

**`public function dispararSeElegivel(Company $company): array`** — o método que os controllers
e o Observer chamam:
1. `$avaliacao = $this->avaliar($company)`. Se `status !== 'elegivel'` → logar em nível `info`
   e retornar a avaliação sem tocar na Clicksign. **Zero chamada** é o Success Criteria 3.
2. Se elegível → `$resultado = $this->clicksign->iniciarParaEmpresa($company)` (o 2º portão da
   D-02 roda dentro dele) e retornar `['status' => 'disparado', 'resultado' => $resultado]`.
3. **Todo o corpo dentro de `try { } catch (\Throwable $e) { }`.** No catch: `Log::error()` com o
   prefixo `[GatilhoContrato]`, id e nome da empresa, e `return ['status' => 'erro', 'erro' => $e->getMessage()]`.
   **Nunca relançar.** Este é o invariante da fase em código: uma falha do gate não pode se
   propagar para quem cadastrou a empresa.

Regras adicionais, obrigatórias:
- **Proibido gravar em `Company`** dentro deste service (`$company->save()`/`->update()`).
  É a 1ª linha de defesa contra o laço da D-04, verificada explicitamente na verificação da fase.
- Guard de reentrância por request: `private static array $emAvaliacao = []` indexado por
  `company_id`, setado no início de `dispararSeElegivel()` e limpo no `finally`. Se a empresa já
  está sendo avaliada nesta mesma execução, retornar `['status' => 'reentrancia_ignorada']`
  imediatamente. Isso corta o laço Observer → disparo → gravação → Observer antes de chegar no banco.
- Logs no padrão do projeto: prefixo `[GatilhoContrato]`, sempre com `empresa {id} ({nome})`.
- Docblock de classe em pt-BR explicando que este é o ponto ÚNICO de decisão (mesmo papel do
  `EmpresaOperacionalRouter` para o roteamento) e que ele roda **em paralelo** ao roteamento,
  nunca no lugar dele.
