## Decisões importantes registradas

**D-01: Single role middleware `role:admin`**
- *Por quê:* CONTEXT D-02 trava acesso só para admin. Diferente da Phase 23 (que abriu para consultor+mentor), aqui não há benefício operacional para consultores/mentores — eles veem `Dashboard` com sua carteira ativa; Painel Executivo é decisão estratégica do admin. Sintaxe `role:admin` (single, sem `|` ou vírgulas).

**D-02: 5 chamadas ECF Drive sequenciais no `index` (sem paralelização)**
- *Por quê:* Cache do wrapper já absorve (5min/24h/1h). Em cold cache primeira carga ~5-10s — aceitável para uma view executiva acessada poucas vezes/dia. Paralelizar exigiria `Http::pool` ou ReactPHP/Swoole — complexidade desproporcional ao benefício. Lean. Documentar latência em comentário.

**D-03: Try/catch global retorna props vazias + erro pt-BR (replica padrão Phase 23 D-02)**
- *Por quê:* Qualquer das 5 chamadas pode lançar `RuntimeException` (Phase 22 wrapper). Em vez de quebrar pageload, controller catches `Throwable` e retorna `resumo=null`, `historico=[]`, `breakdowns={programa:{distribuicao:[]}, frete:..., cluster:..., localidade:...}` (4 chaves com distribuicao vazia para o front não quebrar), `erro='Não foi possível buscar dados do painel agora. Tente em alguns segundos.'`. Aceitável porque cache mensal/horário cobre intermitências.

**D-04: Helpers de formatação locais (`fmtMoneyShort`, `fmtPercentSigned`, `fmtMesAno`)**
- *Por quê:* `lib/utils.js::formatCurrency` formata completo (R$ 42.859.191,37) — não cabe nos KPI cards executivos. `lib/utils.js::formatPercent` não tem sinal explícito nem vírgula pt-BR. Criar 3 helpers locais nos componentes onde são usados (módulo `PainelExecutivo`). Trade-off: leve duplicação vs. mudança em utils.js que afetaria outros módulos (regressão). Decisão: ficar local. Se aparecer em mais 1 phase, promover para `lib/utils.js` em fase futura.

**D-05: Helpers locais usam `Intl.NumberFormat('pt-BR', { ... })` (não regex/string manual)**
- *Por quê:* `Intl.NumberFormat` com `signDisplay: 'exceptZero'`, `minimumFractionDigits: 2`, `notation: 'compact'` e `compactDisplay: 'short'` resolve abreviação e sinal nativamente, com vírgula pt-BR garantida. Evita corner cases (zero, negativos, frações exatas).

**D-06: 4 breakdowns carregados de uma vez (não fetch incremental por tab)**
- *Por quê:* CONTEXT D-09 trava. Cache 1h no wrapper torna as 4 chamadas baratas após primeira execução. Frontend troca tab sem fetch (`useState` controlando `activeTab`). Trade-off: payload Inertia ligeiramente maior, mas <50KB total (breakdown=localidade com 50 entradas tem ~5KB). Aceitável.

**D-07: Tab default `programa` (CONTEXT D-09)**
- *Por quê:* É a dimensão estratégica mais lida ("POLOS vs CPP" é a primeira pergunta executiva). `useState('programa')` no `BreakdownTabs.jsx`. Trocar tab muda dataset do gráfico + tabela sem refetch.

**D-08: Localidade limita tabela a top 20 (CONTEXT pitfall 5)**
- *Por quê:* API retorna top 50, mas mostrar 50 linhas na UI vira "muralha de números" não acionável. Limita visual a `slice(0, 20)`. Pizza renderiza top 10 + "Outros" agregado (decisão de UX implicita do CONTEXT — não trava, deixar a critério do executor; mínimo aceitável: pizza com 20 também).

**D-09: Sidebar — posição no topo, próximo do Dashboard (CONTEXT D-03)**
