<objective>
Implementar D1/EDIMG: o editor do Publicador passa de 3 para 4 etapas — Produto → Detalhes →
**Imagens** → Condições de venda — movendo "Fotos e variações" de Detalhes para a nova etapa
Imagens. Causa raiz MEDIDA (não suposta): `EtapaDetalhes.jsx` renderiza `FotosEVariacoes` ANTES de
`FichaTecnica`/`Descricao` — o operador gera imagens antes de preencher qualquer fato do produto, e
é por isso que o Creative Engine (168/169-01/02) planeja 7 slots `SEM_FATO` mesmo quando o cadastro
tem dados que ainda não foram digitados.

⚠️ Esta mudança reverte PARCIALMENTE uma decisão do próprio usuário de 04/10/2026 (comentário de
topo do `Editor.jsx`, commit `cab40d48`): "no Mercado Livre são 3 fases; aqui parecem muitas". O
usuário foi avisado da tensão, recebeu a alternativa mais barata (só inverter a ordem das seções
dentro de Detalhes) e **escolheu a quarta etapa de propósito** — ela também recebe identidade
visual (Fase 170) e acervo (Fase 171). Isto é deliberado, não esquecimento — registrar de novo aqui
para quem ler este plano depois sem o contexto completo da v25.0.

**Achado de código que estreita o escopo deste plano** (divergência entre a coordenação escrita e o
código real, útil para quem negociar com o ECF Dev): a validação por etapa do "Continuar" NÃO mora
em `usePublicador.js` — mora em `apoio.js` (`ETAPAS`/`etapaDoProblema`/`bloqueiosDaEtapa`) e é
CHAMADA direto em `Editor.jsx`. `usePublicador.js` só usa a taxonomia PARALELA de 8 `SECOES` (para
um resumo de progresso), que não muda com este plano. Portanto este plano NÃO precisa tocar
`usePublicador.js` — só `apoio.js`, `Editor.jsx`, `EtapaDetalhes.jsx` e o arquivo novo
`EtapaImagens.jsx`, exatamente os arquivos que o gate já nomeia.

Purpose: o operador preenche fato do produto ANTES de gerar imagem — condição física para TXT-01/03
(169-01/02/03) valerem na prática, não só na API.
Output: 4ª etapa no editor, com a mesma UX de navegação/URL/sessionStorage das 3 atuais.
</objective>
