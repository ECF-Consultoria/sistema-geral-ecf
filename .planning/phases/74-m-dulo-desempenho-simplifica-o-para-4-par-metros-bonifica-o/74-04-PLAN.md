Command `desempenho:consolidar-mes` — assinatura + comportamento:

```
signature: 'desempenho:consolidar-mes {--mes= : YYYY-MM para reprocessar; default = mês anterior ao hoje}'
description: 'Consolida snapshot mensal fechado (dia 1 mês seguinte após sync Adman).'
```

Fluxo:
1. Se `--mes=YYYY-MM` passado, `$mes = Carbon::createFromFormat('Y-m', $mes)->startOfMonth()`. Senão `$mes = Carbon::today()->subMonthNoOverflow()->startOfMonth()`.
2. Itera users elegíveis (mesmo filtro user_setores/cargos.slug IN ['analista','estrategista']) — reusar padrão do `SnapshotDesempenhoScores` linhas 55-65.
3. Para cada user:
   - `$result = $this->scoreService->compute($user, $mes)`.
   - Se `$result['sem_carteira'] === true`, PULAR user (não gravar row — DESEMP-10).
   - Senão, `DesempenhoScoreSnapshot::updateOrCreate(['user_id'=>$user->id, 'mes_referencia'=>$mes->toDateString()], [ref_date=>$mes, score=>(int)round(($result['nota_final']??0)*20), classificacao=>$result['faixa_bonus']??'', tem_base_comparativa=>$result['nota_final']!==null, empresas_carteira=>$result['empresas_carteira'], empresas_eligiveis=>$result['empresas_com_baseline'], breakdown_json=>$result])`.
4. Após lote, popular `ranking_pos` da `mes_referencia` via mesma estratégia de `SnapshotDesempenhoScores::popularRankingPos()` (window function MySQL / fallback iterativo SQLite) — MAS filtrando `WHERE mes_referencia = ?` em vez de `WHERE ref_date = ?`.
5. Log estruturado `[Desempenho Mensal] OK: X · Falhas: Y · Sem carteira: Z` + memory_limit bump `ini_set('memory_limit','512M')` no início do handle (constraint spec: ~15-20 users × ~30 empresas × queries).

Idempotência: `updateOrCreate(['user_id', 'mes_referencia'])` garante rerun no mesmo mês NÃO duplica.
