`App\Services\Sugadores\SugadoresAdsProviderFactory::for(Company $company, ?string $forceName = null)`:
- forceName='adman' → retorna Adman provider sem checar supports()
- forceName='ml' → retorna ML provider sem checar supports()
- sem forceName → checa ML primeiro (cutover Phase 42); Adman como fallback; lança RuntimeException se nenhum suportar

Este padrão se ADAPTA para `MetricsProviderFactory` com uma DIFERENÇA importante:
- Regra de precedência do ADR DATA-04 diz "ML primário, Adman enriquece". Mas o factory retorna UM provider — não é aqui que a fusão acontece. A fusão é responsabilidade do `UnifiedMetricsService` (Plan 60-04). O factory é usado quando o consumidor quer "1 provider por empresa" (ex: badge de origem na UI Phase 61).

<!-- API ML que o provider vai usar (assinaturas exatas): -->

`App\Services\MercadoLivreService`:
- `fetchOrdersSummary(Company $c, string $dateFrom, string $dateTo): array{revenue, sold_quantity, orders_count, sales_fee, raw_orders}` — datas em formato `Y-m-d`
- `fetchAdsSummary(Company $c, string $dateFrom, string $dateTo): array{ad_spend, ad_revenue, clicks, impressions, acos, roas, cpc, sold_quantity}` — datas em formato `Y-m-d`

Ambos podem lançar `RuntimeException` (token expirado, API 5xx, etc). `fetchAdsSummary` já trata internamente 401/404 "no ads" e retorna zeros — mas NÃO trata timeouts nem 5xx.

<threat_model>
## Trust Boundaries

- **Client → MercadoLivreService**: já mitigada por MercadoLivreService (Phase 28). Este plan não introduz nova boundary.
- **App → API ML**: boundary de rede existente; erros de rede/token são traduzidos em DTO com nulls (não vazam para consumidor).
- **Cache pisada**: chave contém company_id — impossível servir cross-tenant.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-03-01 | Denial of Service | Chamadas ML sem cache | mitigate | `Cache::remember` com TTL 900s (ADR); reduz chamadas a 1 por (empresa,período) por janela de 15 min. |
| T-60-03-02 | Information Disclosure | Log de erro pode vazar token | mitigate | Log estruturado NÃO deve incluir `$company->mlToken` inteiro — apenas `company_id` e mensagem sanitizada. Grep no código: nenhum log inclui `mlToken->access_token`. |
| T-60-03-03 | Tampering | Cache poisoning cross-tenant | mitigate | Chave de cache contém `{company_id}` — impossível servir dado de outra empresa. |
| T-60-03-04 | Elevation of Privilege | forceName sem autorização | accept | Método `for()` é chamado internamente; consumidores web NÃO expõem `forceName` como query param. Documentado como override de debug/CLI. |
</threat_model>
