O binário do Dompdf é comprimido: asserção de string sobre o PDF gerado NÃO é confiável. A régua
desta fase, portanto, é em três camadas — e é isso que o teste deve fazer:

1. **HTML renderizado** (`view('contratos.pdf', [...])->render()`): é onde se assere conteúdo —
   razão social, CNPJ, contato, cada serviço, cada valor formatado, vigência e os placeholders.
2. **CSS da view** (leitura do arquivo): é onde se assere `DejaVu Sans`, `page-break-inside: avoid`
   e a quebra de palavra longa.
3. **Binário** (`Pdf::loadView(...)->output()` via o service): assere apenas que começa com `%PDF-`,
   que tem tamanho plausível e que o caso de nome extremo não estoura nem lança exceção.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dados do banco → HTML do contrato | Razão social, endereço e contato são texto livre vindo de importação (HubSpot/Drive) |
