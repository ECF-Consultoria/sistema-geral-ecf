resultado do `MetricDiffDispatcher` que substitui o eixo marcado `manual`, deriva a margem a
partir do CMV, resolve a base em cascata, e — o ponto que tira a carteira só-Shopee do teto de
3,33 — faz o motor de nota parar de zerar a margem de loja Shopee **quando ela tem CMV lançado**.

`componentes_esperados = 2` para Shopee — os dois precisam ceder para célula manual, ou o
CMV digitado é aceito, gravado, exibido e silenciosamente ignorado pela nota.

Output: `ManualMetricOverrideService`, as quatro emendas cirúrgicas em `CompanyScoreService`,
a propagação do sinal `quality.*_fonte` até a leitura do snapshot, e a suíte que prova cada
decisão.

**Shape que o override PRECISA devolver, idêntico ao do dispatcher** (docblock real em
`app/Services/Metrics/ShopeeMetricDiffService.php:62-72` e `AdmanMetricDiffService.php:97-106`):
chaves de primeiro nível `company_id`, `period`, `metrics`, `quality` (o Shopee acrescenta
`investment` fora de `metrics`). Dentro de `metrics`: `revenue` com
`value`/`prev_value`/`diff_pct`/`diff_source`; `contribution_margin_value` com as mesmas 4;
`contribution_margin_pct` com essas 4 **mais** `diff_pp` — é a única métrica com `diff_pp`.
O override substitui blocos inteiros; **não** inventa chave nova dentro de `metrics`.

**Semântica de `diffPctGuardado`** (`ShopeeMetricDiffService.php:189-196`, idêntica em
`AdmanMetricDiffService.php:647`): devolve `null` se atual for null, anterior for null ou
anterior `<= 0`; senão `round((($atual - $anterior) / $anterior) * 100.0, 2)`. Os dois arquivos
têm cópia própria e privada do método — replicar a MESMA semântica no override, com docblock
citando as duas fontes, é seguir a convenção existente, não criar dívida nova.

**Escala de percentual:** `contribution_margin_pct.value` é percentual em escala 0-100 (a Adman
devolve 27,23 para 27,23%), e `diff_pp` é a diferença aritmética entre dois desses valores.
Logo, margem manual = `(fat − cmv) / fat * 100`.

**Janela de mês cheio (D-05/D-06):** `MetricPeriodResolver::resolve(['period_key' => 'YYYY-MM'])`
já produz `mode='closed_period'` com `current_start`/`current_end` no mês calendário completo
(`app/Services/Metrics/MetricPeriodResolver.php:225-250`). É o **único** ponto de resolução de
período do núcleo — nunca calcular `startOfMonth()`/dias à mão. Para obter "o total daquele
mês", usar `metrics.revenue.value` do `MetricDiffDispatcher::compute()` sobre essa janela —
**nunca** o `diff_pct` dela, que compara contra a janela-de-mesmo-tamanho anterior a ela.

**Custo de HTTP, e como este plano o contém:** `AdmanMetricDiffService::compute()` faz até 2
chamadas HTTP síncronas por `(empresa, janela)` no cache miss, e cada janela tem `cacheKey()`
próprio. Decisão desta fase para a Open Question 2 do RESEARCH: **o custo extra só existe para
empresa que TEM lançamento manual ativo**. O caminho rápido (nenhum lançamento) devolve o
resultado do dispatcher sem nenhuma chamada adicional. Como os lançamentos são uma dezena de
células, e não a base inteira, o fan-out fica limitado a `(células manuais) × 2 janelas`, e não
a `N empresas × 2`. Nenhuma infraestrutura assíncrona nova é introduzida: o caminho já roda
atrás de `computeCached()` e do aquecimento existente.

**O gate que precisa ceder — este é o ponto que faz a fase funcionar ou não.**
`app/Services/Desempenho/CompanyScoreService.php`, dentro de `computeEmpresasScore()`:
- linhas 284-288: `$margemPontos = match (true) { $fonteFinanceira === 'shopee' => null,
  $margemVarPp === null => null, default => $this->reguaMargem($margemVarPp) };`
  Enquanto o primeiro ramo for incondicional, loja Shopee com CMV manual continua com
  `margem_pontos = null` e a nota não muda **nada**.
- linha 315: `$componentesEsperados = $fonteFinanceira === 'shopee' ? 2 : 3;`
  Com margem manual presente, a loja passa a ter os 3 componentes esperados.
- linhas 290-302: o motivo `margem_nao_fornecida_shopee` não pode ser adicionado quando existe
  margem manual.
- linhas 353-358: o array `quality` da linha, onde entram `faturamento_fonte`/`margem_fonte`.
- linhas 395-401: `linhaSemFonte()`, o array `quality` da linha sem fonte financeira.

**Por que a nota muda:** `DesempenhoScoreService::computeNotaFinalPorIndicador()`
(linhas 1803-1830) promedia `margem_pontos` **rejeitando os nulls**, e divide a soma dos três
indicadores pela constante `DIVISOR_NOTA_FINAL = 3`, com indicador ausente valendo zero.
Carteira só-Shopee tem margem sempre nula → teto de (5+0+5)/3 = 3,33. Uma única loja com
margem manual já tira a carteira desse teto.

**Fronteira de escopo travada — o override NUNCA se aplica a linha `sem_fonte`.** A linha
sem fonte financeira elegível retorna cedo (linhas 243-250) e nunca chega ao dispatcher. Isso
é intencional e **protege a trava D-91-01** (learnings §0.1): carteira sem nenhum vínculo
financeiro não recebe nota oficial, e um lançamento manual não pode ser a porta dos fundos para
ela receber. Documentar isso no docblock e cobrir com teste.

**Fronteira de escopo travada — o override NÃO toca o caminho legado.**
`DesempenhoScoreService::computeVarMargem()` e `margem_amostra.legado` continuam como estão:
são metadados de auditoria (`nota_final_legado`) e **não decidem bônus**. Consequência aceita e
declarada: os números legados podem divergir dos oficiais quando houver célula manual.
