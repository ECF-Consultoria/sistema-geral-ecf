<objective>
Entregar o instrumento de decisão da retroatividade: um comando Artisan **read-only** que diz
quais empresas mudam de fonte financeira por causa da correção de D-10, quais profissionais as
têm na carteira, e quantas células manuais existem na competência.

Purpose: D-11 é explícito — a fase **não** reconsolida competência fechada. Learnings §2: qualquer
recompute mexe em pagamento de quem está perto da fronteira de 4,00, e junho já foi reconsolidado
uma vez, saindo de 5 contemplados para 1. A reconsolidação precisa ser ato separado, deliberado,
com backup. Este comando é o que coloca o número na mesa para essa decisão — e é também a
reconciliação contra produção que o RESEARCH (A1) exige antes de considerar D-10 encerrado, já
que o banco local mentiu sobre o `cust_id` de pelo menos uma empresa conhecida.

Output: `desempenho:relatorio-impacto-fonte`, com `--mes=` e `--json`, e a suíte que prova que
ele não escreve nada.
</objective>

**Analog exato:** `app/Console/Commands/VerificarConsolidacaoDesempenho.php` (361 linhas,
read-only comprovado). Copiar quatro coisas dele:

*(a) Assinatura e contrato de saída* (linhas 83-87): `protected $signature` multi-linha com
`{--mes= : YYYY-MM (default = mês anterior ao hoje)}` e
`{--json : saída em JSON, parseável, sem nenhum outro texto}`, e `$description` declarando que
o **exit code é o veredito, nunca o texto impresso**.

*(b) `handle(): int`* (linhas 89-122): parse de `--mes` com
`Carbon::createFromFormat('Y-m-d', $mesOption . '-01')` — **nunca** `'Y-m'` sozinho; monta o
relatório; imprime `json_encode($relatorio, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE)` quando
`--json`, senão a tabela humana; e devolve `self::SUCCESS`/`self::FAILURE` a partir de um
contador do próprio relatório.

*(c) Docblock declarando READ-ONLY explicitamente* (linhas 28-34): "este comando não grava nada
— nenhuma escrita em nenhuma tabela, nenhum cache aquecido, nenhuma chamada ao serviço que monta
o payload de nota (isso dispararia HTTP à Adman). Um verificador que corrige o que encontra
esconderia a inconsistência em vez de expô-la".

*(d) Aviso de que a tabela humana não é o contrato* (linhas 314-320 e 358): `$this->warn(...)`
dizendo que a saída de texto é conveniência humana e que a conferência oficial é o exit code ou
o `--json`.

**Semântica de exit code desta fase, declarada no `$description` e no docblock:**
`0` = nenhuma empresa muda de fonte e nenhuma célula manual ativa na competência — nada a
decidir. `1` (`self::FAILURE`) = existe impacto listado, e a decisão de reconsolidar é do
usuário. É a mesma convenção do vizinho (exit code é o veredito), com o veredito adaptado ao que
este comando mede.

**Regra antiga versus nova.** A antiga é literalmente
`$sources->contains('adman') ? 'adman' : $sources->first()`; a nova é
`FinancialSourceResolver::resolverPorEmpresa()` (Plano 01), que exige `Company::cust_id` não nulo
para `'adman'` vencer. O comando calcula as duas para a MESMA entrada e lista as diferenças.
Manter a expressão antiga **apenas** dentro deste comando, com comentário pt-BR dizendo que é a
regra revogada, preservada aqui só para produzir a coluna "antes" do relatório — é o mesmo
padrão de `setIncluirImputadas(false)` em `DesempenhoScoreService` (linhas 143-151), que existe
exclusivamente para o relatório de impacto de uma fase enxergar o valor pré-regra.

**Universo a percorrer.** Vínculos de `company_users` com `servico_id` em `servicos` de setor
`performance` ou `shopee` (os dois que `CarteiraContextService::flagsFinanceirasPorSetor()`
marca como elegíveis, `app/Services/Portfolio/CarteiraContextService.php:247-276`), empresas
`active = true`, com `distinct` — `company_users` tem várias linhas por (empresa, papel), uma
por serviço desde a Fase 76 (learnings §7), e sem `distinct` a mesma empresa é contada em duas
carteiras. Só empresas com **mais de uma** fonte concorrente podem mudar de resultado; as demais
não precisam sequer entrar na comparação.

**Privacidade (learnings §11) — restrição dura.** O relatório pode versionar **contadores** por
profissional (quantas empresas mudam, quantas células manuais). **Não pode** emitir nota final,
faixa de bônus nem valor de bonificação, nem parear nome com nenhum desses. O comando
deliberadamente **não** recalcula nota: além do risco de privacidade, recalcular chamaria
`MetricDiffDispatcher::compute()` e dispararia HTTP síncrono à Adman, quebrando a disciplina
read-only.

**Contagem de células manuais** — consultar `desempenho_metricas_manuais` diretamente (fonte de
verdade indexada, `ativo = true`, `whereDate('mes_referencia', ...)`), agrupando por `metrica`.
Foi por isso que esta fase decidiu **não** criar coluna dedicada no snapshot (Open Question 3 do
RESEARCH): a contagem sai da tabela própria, não de agregação sobre JSON.

**Gate FIXMARG-03 — o que este comando NÃO faz.** D-10 move
`margem_amostra.legado.n_elegivel` (`DesempenhoScoreService.php:1532-1534`, que filtra
`$fontes[$c->id] !== 'shopee'`), o que alimenta o gate de cobertura que recusa congelar abaixo de
0,7 (`ConsolidarMesDesempenho.php:219-225`, constante `MARGEM_COBERTURA_MINIMA_CONGELAMENTO`).
A conferência desse gate é feita por `desempenho:verificar-consolidacao --mes=YYYY-MM --json`,
cujo veredito é o **exit code** — não é papel deste comando duplicar aquela verificação. Citar o
comando vizinho no docblock, para quem ler saber onde conferir.
Armadilha de shell já registrada (learnings §4): `comando | tail -20; echo $?` devolve o exit
code do `tail`. Capturar antes do pipe ou redirecionar para arquivo.

**Ambiente:** `php` NÃO está no PATH do Bash tool. Usar sempre `C:\xampp\php\php.exe`.
**Deploy proibido sem autorização** — a execução contra produção fica para quando houver.
**Árvore compartilhada:** sempre `git commit -- <caminhos>`, NUNCA `git add -A`.
