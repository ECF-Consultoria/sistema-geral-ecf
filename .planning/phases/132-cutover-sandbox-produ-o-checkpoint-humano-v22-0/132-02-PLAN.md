<objective>
Virar a chave: fazer o sistema em produção parar de conversar com a Clicksign de teste e passar a
conversar com a de verdade — **conferindo cada passo**, nunca assumindo.

Propósito: "é só trocar a URL" é exatamente a frase que esta fase existe para desmentir. São cinco
variáveis (não quatro), mais dois passos de servidor que, se esquecidos, fazem o sistema continuar
no ambiente antigo enquanto todo mundo acha que virou.

⚠️ **Antes de trocar qualquer credencial, este plano LIGA o interruptor de emissão (D-07).** A partir
do momento em que as credenciais viram produção, o sistema fica vivo contra a Clicksign real — mas a
aprovação final só acontece no plano 132-04, e entre as duas coisas podem passar horas ou dias.
Sem o interruptor, qualquer administrador fazendo o trabalho normal do dia geraria um contrato de
verdade para um cliente de verdade — e a API **não cancela** contrato em andamento.

Saída: as seções SC1, SC4 e o campo "Interruptor de emissão" do `132-GATE.md` preenchidos com o que
foi conferido, lido do servidor, com data/hora e autor.

⚠️ **Este plano NÃO cria contrato nenhum.** Depois dele o sistema está apontado para produção, mas
nada foi enviado a ninguém. O primeiro contrato é o plano 132-03.

⚠️ **Nenhuma task deste plano escreve código.** Se alguma conferência reprovar, a correção vira
plano de gap (`/gsd:plan-phase --gaps`), não uma edição improvisada no meio da virada.

**As cinco variáveis que mudam** (todas em `config/services.php`, bloco `clicksign`):

| Variável | Hoje (teste) | Depois (produção) |
|---|---|---|
| `CLICKSIGN_ENV` | `sandbox` | `production` (ou `producao`/`produção`/`prod` — as 4 valem depois do plano 132-01) |
| `CLICKSIGN_BASE_URL` | `https://sandbox.clicksign.com/api/v3` | `https://app.clicksign.com/api/v3` |
| `CLICKSIGN_ACCESS_TOKEN` | token do sandbox | token da conta de produção |
| `CLICKSIGN_WEBHOOK_SECRET` | secret do sandbox | secret cadastrado no painel de produção |
| `CLICKSIGN_TEMPLATE_ID` | UUID do modelo no sandbox | **UUID do modelo na conta de produção — são DIFERENTES** |

⚠️ **A quinta linha não está no SC1 do ROADMAP.** Está no comentário do próprio
`config/services.php` ("Sandbox e produção têm UUIDs DIFERENTES") e é o tipo de esquecimento que só
aparece quando o primeiro contrato falha — ou, pior, sai com o modelo errado.

**O que NÃO muda:** `CLICKSIGN_API_USER_EMAIL` continua `adm@` (é o usuário da API, não signatário)
e `CLICKSIGN_SIG1/2/3_*` continuam com os nomes e e-mails reais dos três signatários da ECF.

**Variáveis MORTAS:** `CLICKSIGN_PROD_TOKEN` e `CLICKSIGN_PROD_WEBHOOK_SECRET` — **nada em
`config/services.php` as lê**. São o estacionamento onde as credenciais de produção esperaram até
agora. Depois de copiar os valores para as variáveis de verdade, elas devem sumir do arquivo: dois
pares de credenciais no mesmo `.env` confundem exatamente quem está sob pressão.

**O interruptor de emissão** (`app/Services/Clicksign/CongelamentoEmissaoService`, plano 132-01):
chave `contratos_emissao_congelada` na tabela `configuracoes`; ligado, `gerarContrato()` recusa
**antes** de qualquer avaliação e a tela explica o motivo em linguagem simples. Comandos:
- ligar: `php artisan tinker --execute="app(App\Services\Clicksign\CongelamentoEmissaoService::class)->ligar();"`
- conferir: `php artisan tinker --execute="echo app(App\Services\Clicksign\CongelamentoEmissaoService::class)->ativo() ? 'ligado' : 'desligado';"`
⚠️ **Ele NÃO é o interruptor da Fase 128** (`administrativo_bloqueio_ativo`), que barra a liberação
da empresa para o operacional e continua desligado — quem liga aquele é a Fase 133.
⚠️ **Não vive em cache de configuração**: é leitura de banco a cada chamada, então ligar/desligar
vale na hora, sem `config:cache` nem restart. Mas conferir por reconsulta continua obrigatório.

**Ferramenta que já existe e fecha o gate #3** — `app/Console/Commands/ClicksignSondarModelo.php`:
`clicksign:sondar-modelo --listar --producao` faz um `GET /templates` **somente leitura**, exige
confirmação interativa quando o ambiente não é sandbox, e **nunca imprime o token** (por desenho,
`imprimirErroSeguro()`). O modo `--listar` retorna antes de qualquer escrita: sem `--confirmar`,
sem `--criar-modelo`, nada é criado. É a prova empírica da URL base **e** a fonte do UUID do
modelo de produção.

**Os DOIS 403 da Clicksign não podem ser confundidos** (medido — §11.3 do empírico):
- `A conta não possui acesso a essa funcionalidade` → o plano contratado não tem API → decisão comercial
- `E-mail do usuário da API não configurado…` → conta certa, falta preencher um campo em
  Configurações → aba API
Distinguir **pelo `detail`, nunca pelo status**. Em 12/08/2026 a produção devolveu o segundo, o
campo foi preenchido, e `GET /templates` passou a devolver 200 com o modelo da ECF listado.
