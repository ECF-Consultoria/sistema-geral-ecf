<objective>
Dar ao admin o poder de montar e editar templates pela UI (D-04) sem que ele consiga: apontar um
passo para um resolver inexistente, criar um ciclo de dependência, ou reescrever a versão em que
onboardings vivos estão rodando.

Purpose: D-07 pede um mecanismo que o projeto nunca fez — versionamento **imutável por linha
nova**. O precedente mais próximo (`nps_templates`) faz o oposto: edita in-place e congela a
resposta por snapshot. Aqui a imutabilidade fica no lado do template: publicar cria uma linha nova
em `onboarding_templates` e 13 linhas novas em `template_passos`, e `onboardings.template_id`
continua apontando para a versão antiga até alguém migrar explicitamente.

A guarda de ciclo (SC-08) também não tem precedente no projeto — grep por "ciclo"/"cycle"/
"topological" não encontrou nada. O que existe é a **forma** de onde uma regra composta cara mora:
`$validator->after()` dentro de `withValidator`, com mensagens por campo. O algoritmo é novo.

Output: service de versionamento, FormRequest com DFS de ciclo, controller e rotas admin.
</objective>

**Shape-alvo de `OnboardingTemplateVersionService`:**
- `publicarNovaVersao(Servico $servico, array $passos, User $publicador): OnboardingTemplate`
  Dentro de `DB::transaction()`: calcula `versao = (max(versao) ?? 0) + 1` para o `servico_id`;
  desativa a versão anterior (`ativo = false`); cria a linha nova com `ativo = true`,
  `publicado_em = now()`, `publicado_por`; insere os `template_passos` novos. **Nenhum `UPDATE` em
  `template_passos` de qualquer versão** — só INSERT.
- `migrarOnboardings(OnboardingTemplate $destino, array $onboardingIds): int`
  Para cada onboarding em `rascunho`/`andamento`: repõe `template_id`; para cada `TemplatePasso` do
  destino sem `OnboardingPasso` correspondente por `chave`, cria o passo faltante em `bloqueado`;
  passos existentes com a mesma `chave` **mantêm** status/valor/`disponivel_em` (o UI-SPEC promete
  isso ao usuário: "passos já concluídos permanecem como estão"); passos cuja `chave` sumiu do
  template novo são marcados `nao_aplicavel`, nunca apagados. Ao fim, `reavaliar()`.
- `detectarCiclo(array $passos): ?array` — DFS sobre `chave => depende_de[]`; devolve `null` sem
  ciclo, ou o caminho do ciclo como array de chaves (`['a','b','a']`) para a mensagem de erro.
- `contarOnboardingsNaVersao(OnboardingTemplate $template): int` — alimenta o aviso do dialog de
  publicar (o UI-SPEC só mostra o dialog quando há impacto real).

**Regras de validação do FormRequest (SC-08/D-09/D-14):**
- `passos` array com ao menos 1 item
- `passos.*.chave`: `string|max:60|regex:/^[a-z0-9_]+$/`, **única dentro do payload**
- `passos.*.titulo`: `required|string|max:160`
- `passos.*.dono`: `required|Rule::in(TemplatePasso::DONOS)`
- `passos.*.setor_id`: `nullable|exists:setores,id`
- `passos.*.depende_de`: `array`; cada item precisa ser uma `chave` **presente no próprio payload**
  e diferente da própria chave do passo
- `passos.*.sla_dias`: `nullable|integer|min:1|max:365`
- `passos.*.auto_fonte`: `nullable|Rule::in(array_column($factory->catalogo(),'chave'))` — a lista
  vem do registry, não de uma constante duplicada
- `passos.*.condicao`: `nullable|array`, com `condicao.tipo` em `Rule::in(TemplatePasso::CONDICOES)`
- `passos.*.obrigatorio`: `boolean`
- Em `withValidator`/`after`: rodar `detectarCiclo()` e, havendo ciclo, adicionar erro no campo
  `passos.{i}.depende_de` do primeiro passo do caminho **e** um erro geral com o texto exato do
  UI-SPEC: `"Não foi possível publicar: ciclo de dependência entre {A} → {B} → {A}. Ajuste as
  dependências e tente novamente."`

**Rotas (dentro do grupo `['auth','verified','role:admin']`):**
- `GET /onboarding/templates` → `index` (`onboarding.templates.index`)
- `POST /onboarding/templates` → `store` — publica versão N+1 (`onboarding.templates.store`)
- `POST /onboarding/templates/{template}/migrar` → `migrar` (`onboarding.templates.migrar`)

**Atenção de roteamento:** `GET /onboarding/templates` precisa ser declarada **antes** de qualquer
rota `/onboarding/{parametro}` que o Plano 09 venha a criar, senão `templates` é capturado como
