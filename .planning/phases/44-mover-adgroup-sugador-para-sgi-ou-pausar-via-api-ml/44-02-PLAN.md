<objective>
Entrega o backend que realmente chama a API Mercado Ads e move o adgroup. Hoje `SugadorController::move` (legacy Plan 19/30) só registra decisão como audit log — operador faz o move manualmente no painel ML. Pós esta plan, 1 clique no botão "Mover para SGI" do `Show.jsx` (Plan 44-03) dispara `moverSgi` → resolve MLBs do adgroup via `AdgroupMlbMapRepository` → loop N PUTs no ML → grava resultado + abre janela de undo (controller registra `campaign_id_original` em SugadorAcao properties).

3 actions novas:
- `moverSgi`: move pra SGI existente (combobox no Plan 44-03)
- `criarSgiEMover`: cria nova campanha SGI pausada + move atomicamente
- `desfazerMove`: reverte (chamado pelo toast 10s do Plan 44-03)

Falha parcial = sucesso parcial (success >= 1 → status='movido'). Sem rollback automático (RESEARCH §7.2).

Feature flag default-false esconde tudo pra roll-out gradual. Sugadores Adman antigos abortam 422.

Purpose: prover infraestrutura backend testável via HTTP independente da UI. Plan 44-03 só consome. Garante tratamento consistente de falha parcial e edge cases (403 scope, 404 ad sumido, 5xx) antes da UI existir.
Output: 2 métodos write em `MercadoLivreAdsService`, 3 actions em `SugadorController`, 3 rotas em `routes/web.php`, feature flag em `config/features.php`, 14 tests Feature verdes.
</objective>
