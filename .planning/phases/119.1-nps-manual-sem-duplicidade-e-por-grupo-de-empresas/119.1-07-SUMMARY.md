# Phase 119.1 Plan 07: UI — aviso de link duplicado, prévia de cobertura do grupo e motivo do faltante Summary

**One-liner:** `Nps/Index.jsx` reusa o modal "Gerar link" para avisar quando um link já existe (com o link pra copiar), mostra "Quem vai receber esta nota" com os 5 motivos de exclusão do grupo antes do envio, e explica por que cada empresa está sem link (inclusive "falta cadastrar o contato"); `Nps/Respond.jsx` passa a postar no endpoint de grupo quando aplicável — sem isso o NPS de grupo (Plan 06) não funcionava na prática.

### 1. Aviso de link já existente (modal "Gerar link" → mesmo diálogo "Link NPS")

- Título: **"Já existe um link deste mês"**
- Corpo, modo empresa: *"Esta empresa já tem um link de NPS deste modelo neste mês. Enviar um segundo link pode fazer o cliente responder duas vezes. Use o link abaixo."*
- Corpo, modo grupo: *"Este grupo já tem um link de NPS deste modelo neste mês. Enviar um segundo link pode fazer o cliente responder duas vezes. Use o link abaixo."*
- Cor de destaque: âmbar (bloco copiável com borda/fundo âmbar quando `linkJaExistia`).

### 2. Prévia de cobertura do grupo (modal "Gerar link", seção "Quem vai receber esta nota")

- Cabeçalho: **"Quem vai receber esta nota"**
- Carregando: *"Verificando as empresas do grupo..."*
- Grupo qualificado (nenhuma excluída): *"Todas as {N} empresas do grupo vão receber a nota que o cliente der."* + lista de nomes.
- Grupo parcialmente qualificado: bloco verde *"Vão receber a nota ({N})"* + bloco âmbar *"Não vão receber ({M})"*, um item por empresa excluída com o motivo:
  - `responsavel_diferente` → *"{empresa} — o {serviço} desta empresa é cuidado por outra pessoa ({quem_cuida}). Ela continua com nota 1 no mês até você gerar um link só para ela."*
  - `sem_servico_contratado` → *"{empresa} — não tem {serviço} contratado, então este modelo de pesquisa não se aplica a ela."*
  - `sem_servico_em_comum` → *"{empresa} — não tem nenhum serviço em comum com as outras empresas do grupo neste modelo de pesquisa."*
  - `ja_tem_link` → *"{empresa} — já tem um link deste modelo neste mês. Ela responde pelo link dela."*
  - `empresa_inativa` → *"{empresa} — está inativa no sistema."*
- Grupo não qualificado (nenhuma incluída): *"Nenhuma empresa deste grupo pode receber este link agora. Veja o motivo de cada uma abaixo."* + botão "Gerar Link" desabilitado.
- Empresa única, sem grupo (modo empresa, sem fetch): *"Esta empresa não faz parte de nenhum grupo. O link vale só para ela."*
- Toggle de modo: **"Uma empresa"** / **"Um grupo de empresas"**.

### 3. Motivo na lista de faltantes (área NPS, chip "Faltantes")

- Badge: **"Sem contato cadastrado"** (`motivo === 'sem_contato'`).
- Texto: *"Esta empresa não tem e-mail nem WhatsApp cadastrado. Sem isso não dá para enviar a pesquisa — e ela fica com nota 1 no mês. Cadastre o contato na página da empresa."*
- `motivo === 'sem_link'` + `conta_nota_1 === true`: *"Sem link neste mês — já está contando nota 1."*
- `motivo === 'sem_link'` + `conta_nota_1 === false`: *"Sem link neste mês — ainda dá tempo de enviar."*
- Resumo no topo (`contadores.contam_nota_1 > 0`): *"{N} empresa(s) estão contando nota 1 por não terem recebido pesquisa neste mês."*

## Decisions Made

- **`grupos` escopado como `NpsGrupoController::autorizarAcessoAoGrupo`:** admin vê todos os grupos; não-admin só vê grupo cujas empresas estão TODAS na carteira dele. Nunca parcial — não pode nem saber que um grupo existe se ele tiver 1 empresa fora do escopo do usuário.
- **"Empresa única, sem grupo" é texto fixo, sem fetch:** no modo "Uma empresa", a seção "Quem vai receber esta nota" mostra sempre essa frase (não depende de o front saber se aquela empresa específica tem `company_group_id`) — evita um fetch extra só para essa informação, e o texto é neutro o suficiente (reforça que o link vale só para a empresa escolhida, que é sempre verdade no modo individual).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing Critical] `NpsController::index()` sem prop `grupos` — o seletor de grupo não tinha o que listar**
- **Encontrado durante:** Task 2, ao implementar o seletor "Um grupo de empresas".
- **Issue:** O frontmatter do plano declarava `files_modified: [Nps/Index.jsx, Nps/Respond.jsx]`, mas nenhum dos dois arquivos tem acesso à lista de `CompanyGroup` — sem uma prop com id/name, o toggle "Um grupo de empresas" ficaria sem nenhuma opção pra selecionar, e o NPS de grupo (entregue no backend pelo Plan 06) ficaria inacessível na prática.
- **Fix:** Adicionada a prop `grupos` em `NpsController::index()` (`id`, `name`), escopada com a MESMA regra de `NpsGrupoController::autorizarAcessoAoGrupo()` — não-admin só vê grupo em que TODAS as empresas estão na carteira dele.
- **Arquivos:** `app/Http/Controllers/NpsController.php` (arquivo além do `files_modified` declarado no plano).
- **Verificação:** `--filter=Phase119_1` → 102/102 passed (baseline exata — a prop é aditiva, nenhum teste existente consome/depende dela).
- **Committed in:** `75e89733` (Task 2).

**2. [Rule 2 — Missing Critical] `Nps/Respond.jsx` sem consumo de `survey.submit_url` — NPS de grupo não funcionava de fato**
- **Encontrado durante:** Task 2, seguindo a instrução explícita do plano ("Se isso não for feito, o NPS de grupo não funciona na prática").
- **Issue:** O Plan 06 já expunha `survey.submit_url`/`survey.is_grupo` no payload público, mas `Nps/Respond.jsx` sempre postava em `route('nps.submit', survey.token)` (rota individual) — um cliente respondendo o link de grupo receberia 404/comportamento errado, pois o token de grupo não existe na tabela de surveys individuais.
- **Fix:** `submit()` agora usa `survey.submit_url ?? route('nps.submit', survey.token)` — grupo posta em `nps.grupo.submit`, individual mantém o comportamento de sempre (fallback preserva 100% dos surveys pré-existentes, que nunca tiveram essa chave no payload).
- **Arquivos:** `resources/js/Pages/Nps/Respond.jsx` (já estava no `files_modified` do plano).
- **Verificação:** `npm run build` verde; `grep -c "submit_url" Respond.jsx` → 3 (declaração da variável + comentário + uso).
- **Committed in:** `75e89733` (Task 2).
