## Pattern Assignments

### 1. Guard de duplicidade em `NpsController::generate()`

**Analog:** `app/Console/Commands/NpsDispararMensal.php` (guard `$jaExiste`, linhas 220-231)

**O guard exato a replicar:**
```php
// Source: app/Console/Commands/NpsDispararMensal.php:223-231
$jaExiste = NpsSurvey::where('company_id', $empresa->id)
    ->whereDate('month_reference', $mesAtual)
    ->where('template_id', $modelo->id)
    ->exists();

if ($jaExiste) {
    $puladosIdempotencia++;
    continue;
}
```

**Onde encaixa em `generate()`** (`app/Http/Controllers/NpsController.php`): entre a resolução do `$template` (linha 1013, fim do bloco `if/else` de resolução de template) e o `NpsSurvey::create(...)` (linha 1015). Hoje **não existe nenhuma query de verificação** nesse intervalo — confirmado lendo linha a linha.

**Diferença crítica a tratar (não existe no analog):** `month_reference` nasce **sempre NULL** em `generate()` (comentário do próprio código, linha 1026-1027: *"month_reference fica null para manuais (D-12)"*). O guard não pode comparar `month_reference` diretamente — precisa usar o MESMO fallback `month_reference ?? created_at` que `NpsImputationService::materializar()` já usa para calcular `competencia_nps` (citado no RESEARCH C1). Ou seja, o guard novo deve comparar contra a competência resolvida por esse fallback, e não contra a coluna crua.

**Shape sugerido do guard novo** (mesma forma do `$jaExiste`, adaptado à ausência de `month_reference`):
```php
$competenciaAtual = now()->startOfMonth();

$jaExiste = NpsSurvey::where('company_id', $data['company_id'])
    ->where('template_id', $template->id)
    ->where(function ($q) use ($competenciaAtual) {
        $q->whereDate('month_reference', $competenciaAtual)
          ->orWhere(function ($qq) use ($competenciaAtual) {
              $qq->whereNull('month_reference')
                 ->whereBetween('created_at', [
                     $competenciaAtual->copy()->startOfMonth(),
                     $competenciaAtual->copy()->endOfMonth(),
                 ]);
          });
    })
    ->first(); // usar o objeto (não ->exists()) para poder devolver o link existente
```

**Decisão de UX pendente (C1/A4 do RESEARCH — Claude's Discretion):** bloqueio duro vs. "aqui está o link já existente". O RESEARCH recomenda a segunda opção (mais útil operacionalmente) — se o `$jaExiste` encontrar um survey `pending`/`expired`, devolver `back()->with(['error' => '...', 'nps_link' => route('nps.respond', $survey->token)])` reaproveitando o MESMO padrão de flash que a criação bem-sucedida já usa (linha 1057-1060).

**Padrão de flash Inertia a reusar** (sucesso, para espelhar no bloqueio):
```php
// Source: app/Http/Controllers/NpsController.php:1057-1060
return back()->with([
    'success'  => 'Link NPS gerado com sucesso.',
    'nps_link' => route('nps.respond', $survey->token),
]);
```

### 2. Fallback de leitura "empresa sem survey conta 1" (D1) — generalizar o precedente da Fase 118

**Analog exato:** `app/Services/Desempenho/NpsPorEmpresaService.php` — `houveSurveyPorEmpresa()` (linhas 468-494) + `linhaSemNota()` (linhas 501-516). **`houveSurveyPorEmpresa()` — íntegra:**
```php
// Source: app/Services/Desempenho/NpsPorEmpresaService.php:468-494
private function houveSurveyPorEmpresa(Collection $companyIds, Carbon $inicio, Carbon $fim): array
{
    $ids = $companyIds->values()->all();

    if (empty($ids)) {
        return [];
    }

    $comSurvey = NpsSurvey::query()
        ->whereIn('company_id', $ids)
        ->where(function ($q) use ($inicio, $fim) {
            $q->where(function ($qq) use ($inicio, $fim) {
                $qq->where('status', 'completed')
                    ->whereBetween('completed_at', [$inicio, $fim]);
            })->orWhereBetween('month_reference', [$inicio->toDateString(), $fim->toDateString()]);
        })
        ->pluck('company_id')
        ->unique()
        ->all();

    $map = [];
    foreach ($ids as $id) {
        $map[$id] = in_array($id, $comSurvey, true);
    }

    return $map;
}
```

**Analog para o shape de criação de `NpsSurvey`:** `NpsController::generate()` (linhas 1015-1028) e `NpsDispararMensal.php` (linhas 252-263) — dois exemplos reais do shape esperado.

3. Chama `NpsSnapshotService::registrar($response)` uma vez por empresa-espelho — **sem modificar o serviço**.

### 4. Resolução de responsável por serviço — comparação "mesmos responsáveis" no grupo

**Analog:** `Company::responsavelDoServicoOuConsolidado(string $role, int $servicoId)` (`app/Models/Company.php:246-263`)

**Método íntegro:**
```php
// Source: app/Models/Company.php:246-263
public function responsavelDoServicoOuConsolidado(string $role, int $servicoId): \Illuminate\Support\Collection
{
    $especificos = $this->belongsToMany(User::class, 'company_users')
        ->wherePivot('role', $role)
        ->wherePivot('servico_id', $servicoId)
        ->distinct('users.id')
        ->get();

    if ($especificos->isNotEmpty()) {
        return $especificos;
    }

    return $this->belongsToMany(User::class, 'company_users')
        ->wherePivot('role', $role)
        ->wherePivotNull('servico_id')
        ->distinct('users.id')
        ->get();
}
```

```php
// Source: app/Services/DesempenhoScoreService.php:883-911 (notasPorAtribuicao)
return NpsScoreAssignment::query()
    ->join('nps_responses as r', 'r.id', '=', 'nps_score_assignments.nps_response_id')
    ->join('nps_surveys as s', 's.id', '=', 'r.survey_id')
    ->where('nps_score_assignments.user_id', $user->id)
    ->where('s.status', 'completed')
    ->whereBetween('s.completed_at', [$inicio, $fim])
    ->whereNull('r.invalidated_at')
    ->when($invalidadas && $invalidadas->isNotEmpty(),
        fn ($q) => $q->whereNotIn('s.company_id', $invalidadas->all()))
    ->groupBy('nps_score_assignments.nps_response_id', 'nps_score_assignments.role')
    ->selectRaw('nps_score_assignments.nps_response_id as response_id,'
        .' nps_score_assignments.role as role,'
        .' MAX(nps_score_assignments.average_score) as average_score')
    ->get()
    ->map(fn ($row) => (object) [
        'response_id'   => (int) $row->response_id,
        'role'          => (string) $row->role,
        'average_score' => (float) $row->average_score,
    ]);
```

**Por que a arquitetura de N surveys-espelho REAIS (item 3) satisfaz as duas réguas sem gambiarra:** cada empresa-espelho gera seu PRÓPRIO `survey_id`/`nps_response_id` distinto → a área NPS conta 1x por survey por dimensão (N surveys = N contagens, correto); o bônus conta 1x por `(response_id, role)` (N respostas distintas = N contagens, correto). Nenhuma régua precisa saber que a resposta veio de um grupo.
