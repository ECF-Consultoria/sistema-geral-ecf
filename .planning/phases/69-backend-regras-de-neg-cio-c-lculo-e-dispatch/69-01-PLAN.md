<research_reference>
Research §4 (v15-nps-templates-schema.md) fixa a regra determinística:

```php
public function resolveForCompany(Company $company): NpsTemplate
{
    $servicoIds = $company->contratosServico()->active()->pluck('servico_id');
    return NpsTemplate::query()
        ->where('active', true)
        ->whereHas('serviceScopes', fn($q) => $q->whereIn('servico_id', $servicoIds))
        ->orderByDesc('priority')
        ->orderBy('id')
        ->first()
        ?? NpsTemplate::where('is_default', true)->firstOrFail();
}
```

**Atenção pt-BR:** `ContratoServico` expõe `scopeActive()` (linha 74) — NÃO `scopeAtivo()`. Column real é `ativo` bool. Usar `->active()` para conformidade com o padrão v14.0 já provado.

**Precedência:**
1. Templates com pelo menos 1 servico_id em comum + `active=true` → maior `priority` vence; empate por menor `id`
2. Nenhum aplicável → template com `is_default=true` (seed NPS Padrão garante que sempre existe 1)
3. Nenhum is_default (situação anômala — pré-condição do seed 100004 quebrou) → dispara `RuntimeException`
</research_reference>
