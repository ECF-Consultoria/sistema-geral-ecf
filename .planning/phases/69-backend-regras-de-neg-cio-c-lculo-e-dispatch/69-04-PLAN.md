**AUTH pattern — decisão pt-BR:**
Padrão observado no NpsController::index (linha 92-95) e outras controllers: "admin vê tudo, não-admin vê sua carteira via $user->companies()". Para o generate, o mission prompt pede reforçar "admin OR estrategista via pivot company_users.role='estrategista'". Manter forma atual (companies() inclui todos os pivots) mantém compat, mas restringir a estrategista alinha com o Phase 62 padrão citado.

Decisão: preservar comportamento atual (admin OR user tem empresa em qualquer role na pivot). O mission prompt reconhece isso via "consultar quem tem role='estrategista'" — validar via `Company::whereHas('users', fn($q) => $q->where('users.id', $user->id)->wherePivot('role', 'estrategista'))->find($companyId)` seria mais restritivo. Deixar como estatus atual + adicionar path explícito para estrategista (superset seguro).

<research_reference>
Phase 68 SUMMARY confirma: `template_id` é `nullable` no schema (rows Phase 31/33 continuam funcionando sem template). Phase 69 vai popular template_id em toda survey NOVA criada — legado permanece intacto.

Dedup unique parcial (Plan 68-04) é `(company_id, month_reference, template_id) WHERE status=completed AND completed_at NOT NULL`. Como survey manual criado no generate tem `month_reference=null`, ele NUNCA entra no dedup (NULL não colide). Ou seja, generate manual pode co-existir com survey mensal automático da mesma empresa/mês sem violar a unique. Este comportamento é intencional (REQ-31-08).
