`HubspotWebhookController::rotearImplementacao(Company $company, string $nomeServico): void`
(privado, linhas 929-963) — comportamento de HOJE, na ordem exata:
1. `$tipoImpl = ComercialController::servicoDisparaImplementacao($nomeServico)`; se `null`, `return`
2. **guard:** `if (MlbEmpresa::where('company_id', $company->id)->exists()) return;`
3. `polos` → `MlbEmpresa::create(nome, tipo='POLO', projeto='POLOS', company_id)` +
   `MlbImplementacaoFactory::criarParaPolo($mlbEmp)` — **sem segundo argumento**, por isso este
   caminho nunca preenche `gmail_colaborador`
4. `assessoria` → `MlbEmpresa::create(nome, tipo='ASSESSORIA', company_id)`
5. `incubadora` → `MlbEmpresa::create(nome, tipo='INCUBADORA', company_id)`

Chamador (`criarEmpresa()`, linhas 649-651, dentro da `DB::transaction` aberta na linha 513):
```
foreach ($servicosCriados as $nomeServico) { $this->rotearImplementacao($company, $nomeServico); }
```
`$servicosCriados` vem de `persistirContratos()` e é uma lista de **nomes de serviço** (strings) — um
`Servico` só entra nessa lista se existir no catálogo e o contrato for efetivamente criado.

`ComercialController::servicoDisparaImplementacao(string $nome): ?string` — estático, público:
`str_contains` case-sensitive em `'Polos'` / `'Assessoria'` / `'Incubadora'`; qualquer outro → `null`.

Comando de replay: `php artisan hubspot:reprocess-event {id}` →
`App\Console\Commands\ReprocessHubspotEvent` → `HubspotWebhookController::reprocessarEvento()`.
