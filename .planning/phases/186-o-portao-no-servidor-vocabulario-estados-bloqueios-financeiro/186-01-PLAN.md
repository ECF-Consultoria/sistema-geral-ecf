### (a) Primeiro o harness — porque sem ele nenhum gate da fase mede nada

Criar **`tests/gates/verificar-testes.sh`**, o **único** caminho pelo qual esta fase lê saída de
teste. Contrato:

```
sh tests/gates/verificar-testes.sh <plano> <id-do-gate>      # roda e confere
sh tests/gates/verificar-testes.sh --suite <php|js>          # a suíte INTEIRA, para baseline
sh tests/gates/verificar-testes.sh --autoteste               # prova que as formas REPROVAM
```
⚠️ O modo **`--suite`** existe para as baselines (suíte inteira, sem `--filter`): ele **imprime a
linha de forma fixa** (`PHP: <T> / <A> / <F>` ou
`JS: <T> / <P> pass / <F> fail / <S> skipped`) para ir direto ao `186-BASELINES.md`, e **recusa**
sair 0 quando há `failed`/`error` acima do esperado. ⚠️ É o único modo que aceita contagem
**acima** da referência (a sessão paralela acrescenta testes) — e **nunca** abaixo.

Ele lê `tests/gates/contagens-186-<plano>.txt`, uma linha por gate:
```
<id>  js   <arquivos separados por espaço>  ::  tests=<N>[,<N-mutado>]
<id>  php  <filtro-por-metodo>              ::  tests=<N> assertions=<A>
```

Regras de implementação, cada uma com o motivo medido:
1. **ANSI removido ANTES de filtrar** (`sed -E 's/\x1B\[[0-9;]*[A-Za-z]//g'`): as sequências de cor
   já comeram **12 linhas de veredicto** neste projeto e a campanha pareceu verde sem provar nada.
2. **JS:** `node --test --test-reporter=tap <arquivos>`; exigir `^# fail 0$` **e** `^# tests <N>$`.
   ⚠️ **Sem o `tap` o gate é vazio ao contrário:** o reporter `spec` do Node v24.14.0 emite
   `ℹ tests N` (U+2139) e o `grep` por `# tests` **nunca casa**.
3. **PHP:** `C:/xampp/php/php.exe artisan test --filter=<metodo>`; **recusar** qualquer linha
   `Tests:` que contenha `failed` ou `error`, **e** exigir
   `Tests:[[:space:]]+<N> passed \(<A> assertions\)`.
   ⚠️ `artisan test --filter=` numa **classe inteira** passa dos 120 s do shell — **só filtro por
   método** é aceito; o helper **recusa** filtro sem `test_` no começo.
