  conjunção. O caso literal da §9 que TEM de dar true:
  `Combit 4 Cadeira Escritório + 1 MESA REDONDA`.

Completar o serviço com a parte que consulta, construtor com
`private ProgramasPublicadorService $programas`:

`sugerirPara(PubProduto $p): ?array` devolvendo
`['base_id' => int, 'base_sku' => string, 'base_nome' => string, 'quantidade' => ?int,
'origem' => 'portal'|'sku'|'nome', 'conflito_heuristica' => bool]` ou null.

Ordem:

1. Guardas que devolvem null na hora: `$p->produto_base_id !== null`;
   `$p->kit_sugestao_recusada_em !== null`; `$p->kits()->exists()`
   (⚠️ sem usar a relação — o 175-02 é o dono do model e roda em paralelo; use
   `PubProduto::where('produto_base_id', $p->id)->exists()`).
2. **Camada de fato (Portal).** Se `$p->oferta_id` não é nulo: carregue a
   `EstruturaOferta` com `componentes`. Se `fase === FASE_SIMPLES` → não é kit,
   devolve null. Se houver **2 ou mais** componentes → kit misto, devolve null.
   Se houver **exatamente 1** componente com `quantidade >= 2` → procure o
   `PubProduto` daquele `componente_id` (`where('oferta_id', $componente->componente_id)`)
   dentro de `produtosQuery` da mesma conta; achou e ele não é kit → sugere com
   `origem = 'portal'` e `quantidade` = a quantidade do componente. Não achou →
   devolve null (sem cair na heurística: a composição já disse que é combo, e
   adivinhar base por nome contra um fato parcial é pior que não sugerir).
3. **Camada de heurística** (só quando `oferta_id` é nulo). `ehMisto($p->nomeExibido())`

   `$this->programas->produtosQuery($empresa, $company)` + `whereNull('produto_base_id')`
   + `whereKeyNot($p->id)`, e para cada um teste `porSku` e `porNome`. Junte os
   que casaram e passe por `escolher()`. A quantidade vem do `porNome`; se só o
   SKU casou, a quantidade é null (campo vazio, como a §6 manda).
4. `conflito_heuristica`: quando a camada 2 sugeriu E a heurística, rodada por
   diagnóstico, apontaria outro base. Vale o Portal; a flag entra no retorno para
   a tela poder avisar e para o log.
