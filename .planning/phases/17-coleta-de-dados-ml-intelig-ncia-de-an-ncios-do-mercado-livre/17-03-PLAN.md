<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyword (input usuário, via MlbColeta) → query param de endpoints ML | texto não confiável usado só como query param, nunca como URL |
| credenciais ML (config) → app token em Cache server-side | segredo nunca exposto ao cliente nem ao log |
| respostas da API ML (terceiros) → resultado persistido | dados externos; podem conter texto de perguntas (sem dados pessoais) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-06 | Tampering | keyword via query param | mitigate | Keyword validada no controller (Plan 17-04, max:255) e passada SOMENTE como query param `q=` via `Http::get(..., $query)`; nunca concatenada na base URL. |
| T-17-07 | Elevation (SSRF) | endpoints ML | mitigate | `API_BASE` e todos os paths são constantes hardcoded; keyword nunca vira parte do host/path. Sem URL dinâmica controlável pelo usuário. |
| T-17-08 | Information Disclosure | app token em log | mitigate | Token vive só em Cache server-side (`ml_app_token_coleta`); jamais logado. Logs trazem apenas id da coleta + keyword + status. |
| T-17-09 | Privacy | perguntas de compradores | mitigate | Persistir apenas o texto da pergunta; NÃO gravar `from_id` nem dados pessoais do comprador no `resultado`. |
| T-17-10 | Denial of Service | rate limit ML (429) | mitigate | `usleep(200000)` entre chamadas no loop top-5; backoff em 429 com `Retry-After` (cap 30s); Job tries=2/backoff. |
</threat_model>
