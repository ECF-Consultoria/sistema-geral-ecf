# Plan 34-02: UI cadastro Comercial — campos do close + máscaras CNPJ/Telefone

Wave 2. Depende W1. Paralelo com Plan 34-03 e Plan 34-04.

## Escopo

1. **`package.json`** — adicionar `react-imask` (verificar antes; senão `npm install react-imask --save`). Versão estável atual (~7.x).

2. **`ComercialController::store`** — adicionar à validation:
   ```php
   'nicho'                => 'nullable|string|max:255',
   'dor'                  => 'nullable|string|max:5000',
   'vende_ml'             => 'nullable|boolean',
   'faturamento_mensal'   => 'nullable|numeric|min:0|max:99999999.99',
   'marketplaces_extras'  => 'nullable|array',
   'marketplaces_extras.*' => [Rule::in(['shopee','amazon','magalu','temu','tiktok'])],
   'email_colaborador'    => 'nullable|email|max:255',
   ```
   Persistir junto com os outros campos no `Company::create([...])`.

3. **`Comercial/NovaEmpresa.jsx`**:
   - Imports adicionais: `IMaskInput` de `react-imask`, `useMemo`
   - useForm data ganha 6 campos novos:
     ```js
     nicho: '', dor: '', vende_ml: '', faturamento_mensal: '',
     marketplaces_extras: [], email_colaborador: '',
     ```
   - Input CNPJ substituído por IMaskInput com `mask="00.000.000/0000-00"`
   - Input Telefone substituído por IMaskInput com `mask={[{mask:'(00) 0000-0000'}, {mask:'(00) 00000-0000'}]}` (auto-switch por tamanho)
   - Novo bloco "Informações do close" — pode ir no passo 2 (após serviços) ou criar passo 3 (executor decide; recomendo passo 2 expansível com header "Contexto comercial (opcional)" para não inflar o stepper)
   - 5 checkboxes para marketplaces (helper handleToggleMarketplace que adiciona/remove do array)
   - Select vende_ml: opções '' / 'true' / 'false' mapeadas pra null/true/false no submit

4. **STEP1_FIELDS / STEP2_FIELDS** — atualizar para incluir os novos campos no STEP2 (volta pro passo certo em caso de erro).

## Constraints

- Não fazer deploy
- Manter estética tokens ecf-*
- Mascaras: NÃO validar formato no backend (deixa só fricção UX no front)
- Wizard atual do outro dev (Quick 260612-jyx) — preservar lógica de step + onSuccess + onError
