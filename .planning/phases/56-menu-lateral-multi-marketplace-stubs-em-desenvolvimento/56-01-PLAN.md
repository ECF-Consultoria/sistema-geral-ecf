### Task 1 — Estender helper `renderSidebar` para suportar `divider` e `badgeText`

<action>
Em [resources/js/Layouts/AppLayout.jsx](../../../resources/js/Layouts/AppLayout.jsx) modificar o helper `renderSidebar` (linha 313) para renderizar 2 novos tipos de entrada:

**A. Entry tipo `divider`** — quando um child de grupo tem a chave `divider` (string com o label do separador), renderizar UMA linha de label pequeno + hr sutil ANTES dos próximos filhos, sem link nem hover. Exemplo de estrutura (dentro do `.map(child => ...)` de linha ~424):

```jsx
if (child.divider) {
    return (
        <div
            key={`divider-${child.divider}-${idx}`}
            className="pt-3 pb-1 px-3 text-[10px] uppercase tracking-wide text-white/40 select-none"
        >
            {child.divider}
        </div>
    );
}
```

**B. Campo `badgeText` em items de topo** — quando um item de topo (não grupo) tem `badgeText: 'string'`, renderizar badge cinza discreto (padrão `bg-white/[0.08] text-white/50 border border-white/10`) à direita do label, no MESMO slot onde hoje renderiza `showBadge` (linhas 366-370). Precedência: se um item tem AMBOS `badgeText` e `showBadge`, `showBadge` (contador dinâmico) vence — mas na prática nossos stubs (Shopee/Amazon) só usam `badgeText`.

Snippet a inserir logo após o bloco `{entry.showBadge && ...}` (por volta da linha 370):

```jsx
{entry.badgeText && !entry.showBadge && (!collapsed || mobile) && (
    <span className="ml-auto inline-flex items-center h-5 px-1.5 rounded-full bg-white/[0.08] border border-white/10 text-white/50 text-[10px] font-medium shrink-0">
        {entry.badgeText}
    </span>
)}
```

**C. Filtro `itemVisivel` (linha 223-226)** — deve retornar `true` incondicionalmente para entries com `divider` (não têm `permission`/`excludeRoles`). Ajuste sugerido no topo da função:

```jsx
const itemVisivel = (item) => {
    if (item.divider) return true;
    if (item.excludeRoles?.some(r => effectiveRoles.has(r))) return false;
    return item.permission ? permissions.includes(item.permission) : true;
};
```

Sem isso, o `filteredTree` (linhas 234-246) pode dropar o divider se ele não passar no filtro.

**D. Flag `defaultOpen` em grupos** — quando um grupo tem `defaultOpen: true`, seu estado inicial em `openGroups` (linhas 253-265) deve ser `true` MESMO quando não há preferência salva em sessionStorage E a rota atual não bate com nenhum filho. Ajuste na função `useState(() => {...})`:

```jsx
const [openGroups, setOpenGroups] = useState(() => {
    let saved = {};
    try {
        const raw = sessionStorage.getItem(SIDEBAR_GROUPS_KEY);
        if (raw) saved = JSON.parse(raw) || {};
    } catch { /* sessionStorage indisponível — ignora */ }
    NAV_TREE.forEach(entry => {
        if (entry.group) {
            // Auto-open by route match
            if (entry.children.some(c => (pageComponent || '').startsWith(c.page))) {
                saved[entry.group] = true;
            }
            // Auto-open by defaultOpen flag (só se não tiver preferência salva)
            if (entry.defaultOpen && !(entry.group in saved)) {
                saved[entry.group] = true;
            }
        }
    });
    return saved;
});
```

Racional: user pode fechar o grupo ML manualmente — a preferência salva vence sobre `defaultOpen`. Primeira visita (sem sessionStorage), abre por padrão.
