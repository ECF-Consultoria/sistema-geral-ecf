<objective>
O **ponto único** que o ROADMAP pede: `ContratoClicksignService::iniciarParaEmpresa()`. Decide se a
empresa está pronta, congela os dados, cria um `ContratoAssinatura` por serviço ativo e despacha os
jobs — nessa ordem, e nunca gastando chamada HTTP com dado que já sabia estar incompleto.

Purpose: é o Success Criteria 1 e o 5 do ROADMAP inteiros, e é a API que a **Fase 131** (tela do
Administrativo) vai chamar.

⚠️ **Quem grava o `servicos_snapshot` é ESTA fase** — a 126 só lê. É o congelamento da D-10, e ele
existe por um precedente vivido: um `hs_mrr = 0` do HubSpot já zerou 3 contratos de R$ 3.000 neste
projeto por depender de valor lido ao vivo.

Output: um service com contrato de retorno estável, sem rota HTTP nova (a permissão
`admin.contratos` é da Fase 131).
</objective>

    Namespace `App\Services\Clicksign`. Construtor com injeção promovida:
    `public function __construct(private ContratoDadosMinimosService $dadosMinimos) {}`.

    `public function iniciarParaEmpresa(Company $company, ?int $prazoDias = null, ?int $lembreteDias = null): array`

    Sequência **nesta ordem** — a ordem é o requisito, não um detalhe:

    1. **Bloqueio (Success Criteria 1, REDE-05).** `$faltando = $this->dadosMinimos->faltantes($company);`
       Se não estiver vazio, retornar imediatamente
       `['ok' => false, 'faltando' => $faltando, 'criados' => [], 'pulados' => []]`.
       **Nenhuma** chamada HTTP, nenhum PDF, nenhum registro criado. Comentar que este `return`
       precoce é o que protege o orçamento de 15 chamadas contra a janela medida de 20/min.
    2. **Serviços ativos.** `$company->contratosServico()->where('ativo', true)->with('servico')->get()`.
       (A checagem do passo 1 já garante que a lista não está vazia.)
    3. **Um contrato por serviço.** Para cada `ContratoServico`, com índice `$i`:
       a. Guard de UX: `ContratoAssinatura::emAndamentoDoServico($company->id, $cs->servico_id)` —
          se já houver, acrescentar a `pulados` (com o motivo `ja_em_andamento`) e seguir. ⚠️ Este
          guard é **só mensagem amigável**; a garantia real é a constraint (D-05), porque uma
          checagem de código corre risco de corrida entre dois workers.
       b. `try { ContratoAssinatura::create([...]) }` com:
          `company_id`, `servico_id`, `status => STATUS_RASCUNHO`, `prazo_dias => $prazoDias`,
          `lembrete_dias => $lembreteDias`, e `servicos_snapshot => [[ 'servico' =>
          $cs->servico->nome, 'valor_contratado' => (float) $cs->valor_contratado,
          'data_contratacao' => optional($cs->data_contratacao)->format('Y-m-d'),
          'data_vencimento' => optional($cs->data_vencimento)->format('Y-m-d') ]]` —
          **array de UM item** (D-06 + D-10). Comentar que a forma é a que
          `ContratoPdfService::montarDados()` já espera e que o congelamento é deliberado: valor lido
          ao vivo já zerou contrato neste projeto.
          Usar `create()`/`save()` do model, **nunca** `insert()` de query builder — o hook `saving`
          é o que ALIMENTA a trava da D-06.
       c. `catch (\Illuminate\Database\QueryException $e)` com `(string) $e->getCode() === '23000'`
          → acrescentar a `pulados` com motivo `ja_em_andamento` e seguir; qualquer outro código →
          `throw $e`. Copiar o precedente do NPS literalmente. O `catch` envolve o **INSERT**, não o
          dispatch — a violação acontece no INSERT, antes de qualquer job existir, o que reforça o
          Success Criteria 1.
       d. `GerarContratoAssinaturaJob::dispatch($contrato)->delay(now()->addSeconds($i * 5));` —
          o `delay()` escalonado é **camada adicional**, para não lançar N jobs no mesmo segundo e
          reduzir a chance de bater na corrida do `RateLimited`. Ele **não substitui** o bucket
          global: o rate limit é da conta inteira, e duas empresas diferentes disparando ao mesmo
          tempo estouram igual. Comentar isso.
    4. Retornar `['ok' => true, 'faltando' => [], 'criados' => [ids], 'pulados' => [{servico_id, motivo}]]`.

    Docblock de classe em pt-BR registrando as fronteiras, para ninguém "completar" depois:
    - **Não ativa** o envelope (D-02) e **não grava `enviado_em`** — com a ativação acontecendo fora
      do sistema, quem sabe que foi enviado é o webhook da **Fase 129**.
    - **Não expõe rota HTTP** — a tela e a permissão `admin.contratos` são da **Fase 131**; a

    - **Não reusa `PendenciasComerciaisService`** — motivo no plano 127-03 (gate `is_origem_hubspot`
      + não checa e-mail nem CNPJ).
