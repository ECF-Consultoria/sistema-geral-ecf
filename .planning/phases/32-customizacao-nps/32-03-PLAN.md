# Plan 32-03: Logo no Respond.jsx + perguntas dinâmicas

Wave 2 — depende W1. Roda em paralelo com Plan 32-02.

## Escopo

1. **LogoEcf.jsx** — componente reutilizável. Props `theme = 'dark'` (default).
   - Container flex gap 10px, Montserrat 700 42px
   - Texto "ECF" branco
   - Barra `<div>` 4px × 32px com gradiente exato
   - Subtitle 2 linhas "Consultoria<br>& Assessoria" Montserrat 300 12px uppercase letter-spacing 0.12em
2. **app.css** — adicionar import Montserrat 300/700:
   ```css
   @import url('https://fonts.googleapis.com/css2?family=Montserrat:wght@300;700&display=swap');
   ```
   Verificar se ja existe import similar antes de adicionar duplicado.
3. **NpsController::respond()** — ler textos da Configuracao, substituir placeholders via NpsTextRenderer, montar `survey.textos` no payload Inertia.
4. **Respond.jsx** — adicionar `<LogoEcf />` no topo (acima do título atual da pesquisa, no header da pagina). Trocar strings hardcoded das perguntas pelo conteudo de `survey.textos.*`.

## Edge cases

- Cliente cuja survey foi criada ANTES da Phase 32 (não tem o JSON nps_textos atualizado): fallback nos defaults via `NpsTextRenderer` quando `Configuracao::get('nps_textos')` retorna null.
- Mentoria pura (`tem_analista === false`): o bloco de pergunta do analista some inteiro, conforme Phase 31. `survey.textos.perg_analista` ainda vem populado no payload (substituido com `{nome_analista}` = string vazia ou null) mas Respond.jsx não renderiza esse bloco.

## Verificação

- Acesso a `/nps/{token}` (qualquer token válido) mostra:
  - Logo ECF no header
  - 3 perguntas com escala 1-5 (Estrategista, Analista quando aplicavel, Empresa)
  - Textos refletem o que está em `Configuracao::get('nps_textos')` (testar editando via Tinker e refresh da pagina)
  - Placeholders `{nome_estrategista}` foram substituidos pelo nome real
- `npm run build` sem erros
- Build OK + smoke visual em browser
