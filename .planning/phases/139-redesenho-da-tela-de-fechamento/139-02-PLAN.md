<objective>
Criar a prop `totais` que alimenta o widget "Total a receber": soma das mensalidades,
contagem de empresas com cobrança, e o rodapé com mês passado, variação e faturamento
gerado — mais os dois números do widget de upgrades (quantidade e ganho somado).

Purpose: item 3 do D-04. Nenhum desses números existe hoje. E há uma armadilha medida
no código: `TotalConsolidado` filtra por `e.cobranca_mensal_grupo`, prop que o backend
**nunca emitiu** — por isso a captura de produção mostra "0 pagadores com dados" e os
três valores vazios. O total novo não pode repetir esse erro: ele é somado no backend,
a partir das mesmas linhas que a tela lista.

Output: prop `totais` com todos os números do topo da tela, mais os estados de ausência
nomeados (mês passado não fechado, empresas sem valor definido, total que é piso).
</objective>

Em `fechamento()`, **depois** do Passo 3 (agregação por grupo) e antes do
`Inertia::render`, montar a prop `totais` a partir de `$dadosPorId` — as MESMAS linhas
que a tela vai listar. Extrair para um método privado

Considerar apenas as linhas com `conta_no_total !== false`. Nunca usar
`cobranca_mensal_grupo` (chave morta, ver `<interfaces>`).

Shape exato (a tela dos planos 03/04 depende destes nomes):

```
totais: {
  total_a_receber:            float,       // soma de cobranca_mensal das linhas que contam
  total_e_piso:               bool,        // true se ALGUMA linha somada tem valor_faixa_e_piso
  empresas_com_cobranca:      int,         // linhas com cobranca_mensal > 0
  empresas_sem_valor_definido:int,         // linhas com estado 'sem_tabela'
  faturamento_gerado:         float|null,  // soma de faturamento das linhas que contam; null se NENHUMA tem faturamento
  mes_anterior_fechado:       bool,
  mes_anterior_total:         float|null,
  variacao:                   float|null,  // total_a_receber - mes_anterior_total; null quando mes_anterior_total é null
  upgrades_quantidade:        int,         // linhas com subiu_de_faixa === true
  upgrades_ganho_total:       float,       // soma de ganho_faixa das linhas que subiram (ignora null)
  upgrades_ganho_parcial:     bool         // true se alguma linha subiu mas veio com ganho_faixa null
}
```

Regras que não podem ser afrouxadas:
- `cobranca_mensal` null **não** entra na soma como zero; a linha entra em
  `empresas_sem_valor_definido` quando o estado é `sem_tabela`. Sem isso o total sai
  menor que a realidade sem ninguém perceber — a mesma classe de erro que o D-05 proíbe.
- `total_e_piso` existe porque uma faixa-piso torna o TOTAL um piso: a tela precisa
  escrever "a partir de R$ X", nunca o valor seco (disciplina já vigente em
  `fmtValorFaixa`).
- `variacao` só existe se `mes_anterior_total` existe. Mês passado não fechado →
  `variacao` null, e a tela diz isso com palavra, não com R$ 0.
- `upgrades_ganho_parcial` sinaliza que o "+R$ X/mês" do widget está incompleto (alguma
  empresa subiu sem termos o valor da faixa anterior) — a tela mostra "no mínimo".

`mes_anterior_fechado` e `mes_anterior_total` vêm de
`totalCobrancaDoMesAnterior($mesReferenciaStr)` (Tarefa 1).

Passar `'totais' => $this->fechamentoTotais(...)` no array do `Inertia::render`.
Não remover nem renomear nenhuma prop existente. Comentários em pt-BR marcando
`Fase 139 (D-01/D-04)`.
