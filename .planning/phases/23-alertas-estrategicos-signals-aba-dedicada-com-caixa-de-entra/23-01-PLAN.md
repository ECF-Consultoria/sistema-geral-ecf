## Shared prop — alertas_criticos_count

Adicionada em `HandleInertiaRequests::share()` como closure (lazy — só executa quando o JSX lê). Cache 5min via key `alertas.criticos_nao_ackeados.count`. Em erro retorna `null` para que o badge da sidebar desapareça (mesmo padrão silencioso de `sugadores_pendentes`).

```php
'alertas_criticos_count' => fn() => $this->countAlertasCriticos(),

private function countAlertasCriticos(): ?int
{
    try {
        return Cache::remember('alertas.criticos_nao_ackeados.count', 300, function () {
            $ecf = app(\App\Services\EcfDriveService::class);
            $res = $ecf->listSignals(['severity' => 'critical', 'acked' => false, 'limit' => 1]);
            return (int) ($res['total'] ?? 0);
        });
    } catch (\Throwable) {
        return null;  // Badge some na sidebar — falha silenciosa
    }
}
```

## Decisões importantes registradas

**D-01: Middleware `role:admin|consultor|mentor` via varargs do `EnsureUserHasRole`**
- *Por quê:* O middleware existente já aceita varargs (`string ...$roles`). Sintaxe Laravel padrão `role:admin|consultor|mentor` passa os 3 como argumentos separados sem precisar criar middleware novo. Replicação do padrão de outros groups do `routes/web.php` (linhas 316, 356).

**D-02: Try/catch global no `AlertasController::index` retorna props vazias + flash error**
- *Por quê:* Pitfall 1 do CONTEXT. `EcfDriveService::listSignals` pode lançar `RuntimeException` quando API ECF Drive estiver offline. Em vez de quebrar pageload, controller catches `Throwable` e retorna shape vazio: `['data' => [], 'total' => 0, 'page' => 1, 'limit' => 50]` + `stats: ['critical' => 0, ...]` + flash error `'API ECF Drive indisponível agora. Tente em alguns segundos.'`. Aceitável porque cache 1min cobre intermitências e o time pode usar Sugadores enquanto isso (CONTEXT D-03).

**D-03: Lookup companies em batch — UMA query whereIn**
- *Por quê:* Pitfall 2 do CONTEXT. 50 signals/página = 50 cust_ids únicos. Em vez de 50 queries individuais, uma única query `Company::where('active', true)->where(fn($q) => $q->whereIn('adman_account_id', $custIds)->orWhereIn('ml_store_id', $custIds))->get(...)`. Índices em `adman_account_id` e `ml_store_id` já existem desde a Phase 1.

**D-04: 3 chamadas leves cacheadas 1min para stats (não 1 chamada com agregação)**
- *Por quê:* API ECF Drive não tem endpoint de agregação por severidade. `listSignals(['severity' => X, 'acked' => false, 'limit' => 1])` retorna o `total` no shape padrão sem trafegar payloads. Cache de 1min no wrapper (Phase 22) absorve as 3 chamadas → custo efetivo ≈ 1 hit a cada minuto compartilhado entre usuários. Padrão idêntico ao usado pelo `alertas_criticos_count` da shared prop.

**D-05: Shared prop `alertas_criticos_count` com cache 5min e fallback `null`**
- *Por quê:* CONTEXT Pitfall 3. Shared prop roda em CADA pageload Inertia. Cache 5min torna o custo médio insignificante. Em erro retorna `null` em vez de `0` — frontend usa `> 0` para mostrar o badge, então `null` deixa badge invisível silenciosamente. Mesmo padrão de `sugadores_pendentes` (já em produção desde Phase 19).

**D-06: Mirror das constantes TYPE_LABELS / SEVERITY_LABELS / SEVERITY_COLORS no JSX**
- *Por quê:* Constantes vão **também** como props Inertia (`type_labels`, `severity_labels`, `severity_colors`) — fonte da verdade no PHP. JSX espelha objetos JS hardcoded para fallback (mesma estratégia de `STATUS_LABELS` em `Sugadores/Index.jsx`). Manutenção: ao adicionar tipo novo, atualizar AMBOS. Trade-off aceito por consistência com módulos existentes.

**D-07: Ack via `router.post(route('alertas.ack', id), {}, { preserveScroll: true, preserveState: true })`**
- *Por quê:* CONTEXT Pitfall 6. `preserveScroll` evita reset visual quando lista tem 50 itens. `preserveState` mantém filtros aplicados. Após sucesso, Inertia revalida props automaticamente — controller filtra por `acked=false` por default, então o card some da lista. Badge da sidebar decrementa porque shared prop recalcula no próximo navigate (cache 5min expira ou usuário muda de aba — aceitável; cache invalidation manual ficaria over-engineered).

**D-08: Filtros via query string em GET, paginação Inertia padrão**
- *Por quê:* Padrão consagrado no projeto (Sugadores, Empresas, etc.). `Inertia::location` preservado pelo back button. Frontend usa `router.get(route('alertas.index'), { severity, event_type, acked, page }, { preserveState: true })`.

**D-09: Sem persistência local (sem migration, sem model, sem activity log)**
- *Por quê:* CONTEXT D-03. Alertas vivem na API ECF Drive (eles mantêm `ackedAt`). UI consome direto. Decisão lean — duplicar dados localmente exigiria sync incremental, conflito de fonte da verdade, e gasto de tempo zerado de ROI nesta fase.

**D-10: `formatPayload(eventType, payload)` no JSX (não no controller)**
- *Por quê:* Formatação é cosmética e específica de UI (precisa locale BR, símbolos R$, "há 2 horas" via date-fns). Manter no JSX evita serialização extra de strings prontas e mantém controller enxuto. Função pura, testável manualmente no smoke W4.

**D-11: W4 (smoke visual em prod) é checkpoint humano blocking**
- *Por quê:* Mesmo padrão das Phases 19, 20, 21, 22. 778 signals em prod = primeiro teste real de carga + lookup batch + ack flow + badge da sidebar. Sem isso, regressões silenciosas podem se esconder.

## Riscos residuais (documentados — não bloqueiam o plan)

**R-01: API ECF Drive lança em runtime — pageload de OUTRA aba travado pela shared prop**
- Mitigação: try/catch interno em `countAlertasCriticos()` que retorna `null` em qualquer erro. Não propaga para cima. Badge da sidebar simplesmente some.

**R-02: 50 signals/página com payload heterogêneo aumenta peso do JSON Inertia**
- Probabilidade baixa (payload typical < 500 bytes). Mitigação: paginar 50/página (CONTEXT D-06 trava). Se virar dor, reduzir para 25 numa quick task.

**R-03: Badge da sidebar não decrementa imediatamente após ack (cache 5min)**
- Trade-off documentado: ack invalida cache da inbox `/signals` no wrapper (Phase 22 D-04), mas NÃO invalida a chave `alertas.criticos_nao_ackeados.count` desta phase. Usuário vê o card sumir, mas badge fica até o cache expirar (5min) OU usuário navegar entre rotas (closure re-executa). Aceitável — o feedback visual primário é o card sumindo.

**R-04: cust_id de aluno ML não bate com nenhuma Company (matched in Phase 20)**
- Esperado: 395 grants órfãos em prod (alunos de cursos). Comportamento: card mostra `'Cliente externo: {custId}'` sem link. CONTEXT D-08 trava.

**R-05: `ackSignal` lança RuntimeException dentro de POST**
- Mitigação: try/catch no `AlertasController::ack` → `back()->with('error', 'Falha ao marcar como visto. Tente novamente.')`. Não quebra o pageload.

**R-06: Filtros simultâneos via query string podem gerar URLs longas mas funcionais**
- Probabilidade baixa (no máximo 3 params). Mitigação: validação no controller via `$request->validate([...])` com whitelist.

    // Phase 23 — Alertas Estratégicos (caixa de entrada do comercial).
    // Consome /signals da API ECF Drive via EcfDriveService (Phase 22 wrapper).

    namespace App\Http\Controllers;

    use App\Models\Company;

    use Illuminate\Http\Request;

         * Tradução dos event_type da API ECF Drive para labels pt-BR.

        public const TYPE_LABELS = [
            'seller.gmv_queda_mom'     => 'Queda de faturamento',
            'seller.queda_visitas'     => 'Queda de visitas',
            'seller.medalha_rebaixada' => 'Medalha rebaixada',
            'seller.score_critico'     => 'Score crítico',
            'seller.oportunidade_pads' => 'Oportunidade de ADS',

        public const SEVERITY_LABELS = [
            'critical' => 'Crítico',
            'warning'  => 'Atenção',
            'info'     => 'Oportunidade',
        ];

        public const SEVERITY_COLORS = [
            'critical' => 'red',
            'warning'  => 'yellow',
            'info'     => 'blue',
        ];

        public function __construct(private EcfDriveService $ecf) {}

        /**
         * Lista signals com filtros — caixa de entrada do comercial.
         *
         * Estratégia defensiva (D-02): try/catch Throwable global. Se ECF Drive
         * estiver offline, a aba abre normalmente com lista vazia + flash error
         * pt-BR — NUNCA quebra o pageload do usuário.
         */
        public function index(Request $request)
        {
            $validated = $request->validate([
                'severity'   => 'nullable|in:info,warning,critical',
                'event_type' => 'nullable|in:' . implode(',', array_keys(self::TYPE_LABELS)),
                'acked'      => 'nullable|boolean',
                'page'       => 'nullable|integer|min:1',
            ]);

            $filters = [
                'severity'   => $validated['severity']   ?? null,
                'event_type' => $validated['event_type'] ?? null,
                'acked'      => isset($validated['acked']) ? (bool) $validated['acked'] : false,
                'page'       => (int) ($validated['page'] ?? 1),
            ];

            try {
                // 1) Lista paginada de signals
                $apiFilters = array_filter([
                    'severity'   => $filters['severity'],
                    'event_type' => $filters['event_type'],
                    'acked'      => $filters['acked'],
                    'page'       => $filters['page'],
                    'limit'      => 50,
                ], fn ($v) => $v !== null);

                $signals = $this->ecf->listSignals($apiFilters);

                // 2) Lookup batch de companies por cust_id (1 query só — D-03)
                $custIds = collect($signals['data'] ?? [])
                    ->pluck('custId')
                    ->filter()
                    ->map(fn ($v) => (string) $v)
                    ->unique()
                    ->values()
                    ->all();

                $companiesMap = [];
                if (! empty($custIds)) {
                    $companies = Company::where('active', true)
                        ->where(function ($q) use ($custIds) {
                            $q->whereIn('adman_account_id', $custIds)
                              ->orWhereIn('ml_store_id', $custIds);
                        })
                        ->get(['id', 'name', 'slug', 'adman_account_id', 'ml_store_id']);

                    foreach ($companies as $c) {
                        $entry = ['id' => $c->id, 'name' => $c->name, 'slug' => $c->slug];
                        if ($c->adman_account_id) {
                            $companiesMap[(string) $c->adman_account_id] = $entry;
                        }
                        if ($c->ml_store_id) {
                            $companiesMap[(string) $c->ml_store_id] = $entry;
                        }
                    }
                }

                // 3) Stats por severidade (3 chamadas leves, cache 1min no wrapper — D-04)
                $stats = [
                    'critical' => (int) ($this->ecf->listSignals(['severity' => 'critical', 'acked' => false, 'limit' => 1])['total'] ?? 0),
                    'warning'  => (int) ($this->ecf->listSignals(['severity' => 'warning',  'acked' => false, 'limit' => 1])['total'] ?? 0),
                    'info'     => (int) ($this->ecf->listSignals(['severity' => 'info',     'acked' => false, 'limit' => 1])['total'] ?? 0),
                ];

                return Inertia::render('AlertasEstrategicos/Index', [
                    'signals'         => $signals,
                    'companies_map'   => $companiesMap,
                    'stats'           => $stats,
                    'filters'         => $filters,
                    'type_labels'     => self::TYPE_LABELS,
                    'severity_labels' => self::SEVERITY_LABELS,
                    'severity_colors' => self::SEVERITY_COLORS,
                    'erro'            => null,
                ]);
            } catch (\Throwable $e) {
                // Defensiva (D-02): ECF Drive offline NÃO quebra a aba
                report($e);
                return Inertia::render('AlertasEstrategicos/Index', [
                    'signals'         => ['data' => [], 'total' => 0, 'page' => 1, 'limit' => 50],
                    'companies_map'   => [],
                    'stats'           => ['critical' => 0, 'warning' => 0, 'info' => 0],
                    'filters'         => $filters,
                    'type_labels'     => self::TYPE_LABELS,
                    'severity_labels' => self::SEVERITY_LABELS,
                    'severity_colors' => self::SEVERITY_COLORS,
                    'erro'            => 'API ECF Drive indisponível agora. Tente em alguns segundos.',
                ]);
            }
        }

        /**
         * Marca um signal como visto via POST /signals/{id}/ack do ECF Drive.
         * Wrapper invalida automaticamente a chave de cache da inbox padrão.
         */
        public function ack(int $id)
        {
            try {
                $this->ecf->ackSignal($id);
                return back()->with('success', 'Alerta marcado como visto.');
            } catch (\Throwable $e) {
                report($e);
                return back()->with('error', 'Falha ao marcar como visto. Tente novamente.');
            }
        }
    }

## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| Browser → Laravel (Inertia POST) | usuário autenticado envia POST `/alertas-estrategicos/{id}/ack` — entrada não confiável (id na URL) |
| Laravel → API ECF Drive (HTTPS + X-Api-Key) | servidor faz GET/POST autenticado a `files.ecfconsultoria.com.br/api/v1/signals*` — confiamos no certificado e na resposta JSON |
| Inertia shared prop closure → Cache | shared prop `alertas_criticos_count` roda em CADA pageload com possibilidade de chamar API externa |

## STRIDE Threat Register

| Threat ID | Categoria | Componente | Disposition | Mitigation Plan |
|-----------|-----------|-----------|-------------|-----------------|
| T-23-01 | Spoofing | Acesso a `/alertas-estrategicos` por role não autorizada (publicador MLB tentando ver alertas estratégicos) | mitigate | Middleware `auth, verified, role:admin|consultor|mentor` no grupo da rota (W1-T1). Validado por Teste 4 e 5 da suíte (W3-T1) — publicador 403, guest 302. |

| T-23-03 | Tampering | Cliente envia `POST /alertas-estrategicos/9999999/ack` com id arbitrário tentando ackar signal de outra organização | mitigate | A API ECF Drive remota é quem aplica autorização final (a API key do servidor identifica QUAL organização).
